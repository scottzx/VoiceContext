# DEBUG REPORT — Retranscription cascade reset

- **Symptom:** Tapping “重新转写” restarted transcript work without immediately resetting completed speaker-embedding work, so the task center could continue showing stale speaker completion counts and old speaker results during the new transcription pass.
- **Root cause:** The retranscription path reset only the final speaker-finalization job. Existing `speakerEmbedding` jobs, meeting-local speaker bindings, transcript segments, and potentially still-running ASR leases survived the reset. The cancelled-stage restart path also skipped downstream speaker cleanup.
- **Fix:** Full user-triggered retranscription now invalidates the old ASR drain, resets every transcription, speaker-embedding, and speaker-finalization job to pending, clears transcript segments plus meeting-local speaker observations/bindings, and re-enqueues all audio. Partial automatic retry remains non-destructive. The completion reconciler continues to enqueue speaker processing only after all new ASR jobs complete.
- **Evidence:** The new regression failed before the fix because the speaker-embedding job remained `completed`; it passes after the fix. `SpeakerFinalizationStateMachineTests` passed 8/8 and `ProcessingQueueStatusTests` passed 8/8. A physical-device Debug build succeeded, installed, launched, and remained present as process PID 16476.
- **Regression test:** `SpeakerFinalizationStateMachineTests.retranscriptionResetReturnsAllSpeakerJobsToPending` covers transcription count reset, speaker-embedding/finalization reset, and transcript/speaker result clearing.
- **Full suite:** 261 tests ran. The retranscription and processing-state coverage passed; two pre-existing test cases still fail: `RecordingAttachmentTests.attachmentStoreCopiesPrivatelyAndRemovesOnlyItsCopy` and `RecordingCoreTests.completionReconcilerBackfillsFinalizationAndRepairsLostCompletionCallback` (the latter constructs a completed finalization job with a stale pipeline version).
- **Related:** `docs/architecture/staged-speaker-processing.md` defines the dependency order and full-retranscription recovery contract. Global long-term voiceprints are intentionally preserved; only this meeting's derived speaker state is cleared.
