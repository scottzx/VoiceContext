## 1. 产品摘要

VoiceContext 是一款面向苹果生态的本地语音记事本与语音上下文应用。它既能记录多人会议和对话，也能像“闪击胶囊”一样接住用户突然冒出的一个念头、待办、复盘或口述草稿。用户在 iPhone 上明确点击开始记录后，应用在设备本地完成录音、语音活动检测、SenseVoice 转写和说话人聚类。一条 Recording 是 v1 唯一的用户可见记录对象；个人语音笔记、多人讨论和会议共享同一模型，会议只是用户可选开启的结构化模式。

每条 Recording 在内部由若干连续、无重叠的 AAC-LC `AudioChunk` 组成；新录音默认每 60 秒按绝对 16 kHz 样本边界关闭一个 chunk。用户始终只看到一条连续录音。前台中每个 chunk 关闭后立即进入增量 VAD 与转写队列，下一 chunk 同时继续采集，因此正常文稿延迟目标为 0–60 秒加本地处理时间，而不是等待整条 Recording 停止后才开始转写。

产品的核心交付物不是一份由应用擅自生成的固定格式会议纪要，而是一套用户和 Codex 都能直接读取的开放文档：

- 面向人类阅读和复制的 Markdown。
- 面向时间轴、说话人和自动化处理的 JSON。
- 可选同步到公开 `iCloud Drive/VoiceContext` 目录的文本与结构化数据。
- 可由 `generate-meeting-minutes` Codex Skill 按用户自己的模板继续加工的会议逐字稿。

原始音频只保留在录制设备本地。v1 不提供云端 ASR，不内置 LLM 总结，不提供订阅，也不建设业务账号服务器。

## 2. 用户问题与产品机会

现有会议转录或语音笔记产品通常把语音上传到云端，采用订阅收费，并在产品内部输出固定格式的纪要。对目标用户而言存在五个问题：

1. 会议和日常对话可能包含敏感信息，用户希望音频和语音模型处理留在自己的设备上。
2. 订阅价格高，偶尔使用会议转录的用户难以持续支付。
3. 产品内置的通用会议纪要模板往往不符合用户所在公司的格式。
4. 逐字稿被封闭在应用中后，用户无法方便地交给 Codex 或其他桌面工具继续处理。
5. 临时想法出现得很快，先建标题、选类型或填参与人会打断表达；用户需要一个随手开录、稍后整理的个人语言记事本。

VoiceContext 的机会是把 iPhone 变成用户自己的语音上下文采集器与外置语言记忆：先可靠接住一句话、一个念头或一场对话，再完成转写、分人和开放文档输出，把整理方式和模板控制权留给用户。

## 3. 产品定位与原则

### 3.1 产品定位

> 本地、私有、随手可记、可被 Codex 继续加工的个人语音记事本与上下文库。

VoiceContext 不是：

- 云端会议转录服务。
- 自动监听或秘密录音工具。
- 自带固定会议纪要模板的 AI 总结工具。
- 电话录音或其他 App 系统音采集工具。
- 多平台同步音频库。

### 3.2 产品原则

1. **录音可靠性优先于实时转写。** 后台、发热、低电量和内存压力下，先保证音频分片安全落盘。
2. **用户明确开始。** 未经用户点击开始，应用不得访问麦克风。
3. **本地优先。** 录音、VAD、转写和说话人处理在设备本地完成。
4. **音频本地保存。** 原始音频不进入公开 iCloud Drive 目录。
5. **开放文档。** Markdown 是默认阅读入口，JSON 是结构化权威入口。
6. **不伪造结果。** 转写失败保留可重试任务；说话人识别失败保持未知。
7. **身份必须确认。** 疑似匹配不能自动升级为确认身份，未确认声纹不能进入长期档案。
8. **用户控制总结。** 应用不内置 LLM 会议总结，由 Codex Skill 和用户模板完成二次加工。
9. **一次性买断。** 免费试用后提供永久解锁，不依赖订阅和业务服务器。
10. **一个念头也值得完整保存。** 短个人记录不要求主题、参与人或会议结构；先录下来，稍后再命名、加标签或导出。
11. **采集与处理解耦。** 已关闭音频的 VAD、转写、重试或积压不得占用麦克风会话，也不得阻止用户继续当前录音或开始下一条 Recording。

## 4. 目标用户与使用场景

### 4.1 目标用户

- 经常参加产品、项目、销售、研究或内部协作会议，需要可靠逐字稿的人。
- 重视数据隐私，不希望原始录音上传第三方云端的人。
- 已经使用 Mac、iCloud Drive、Files、Finder 或 Codex 处理工作文档的人。
- 有自己的公司会议纪要模板，不希望被应用固定模板限制的人。
- 希望低成本一次性购买，而不是长期订阅会议转录服务的人。
- 习惯自言自语梳理问题、口述灵感、待办、复盘和草稿，希望把 iPhone 当作个人语言记事本的人。

### 4.2 核心场景

#### 场景 A：个人“闪击胶囊”

用户突然想到一个产品判断、待办或文章段落，点击“开始记录”后立即说出内容，不填写标题、不选择类型也不添加参与人。录音结束后以开始时间或首段文本形成可识别标题，详情首先提供音频回听，再展示带时间的文稿；用户可稍后命名、加标签、导出或设为长期保留。“闪击胶囊”是体验隐喻，不是新的数据类型。

#### 场景 B：有主题的结构化记录

用户点击“开始记录”，可直接开始，或勾选“这是一次会议”并补充主题、参与人和议程文本。应用持续录音并在前台显示已转写文本；完成后生成该记录的公开文档。会议模式仅增加结构化字段，不创建另一套录音或浏览路径。

#### 场景 C：无预设主题的多人记录

用户直接开始记录，可在进行中或结束后补充标题、参与人、主题和标签。较长静音可形成多个可阅读片段，但不形成新的用户可见录音对象。所有原始音频默认保留 7 天，用户可按任意记录开启长期保留。

#### 场景 D：修正逐字稿与说话人

用户在记录详情中修改文本、标题、标签、可选会议字段和说话人显示名称，接受或否认“疑似某人”。每次保存增加 revision，并从结构化数据重新生成 Markdown。

#### 场景 E：在 Mac 上交给 Codex

用户启用 iCloud 文本同步后，Mac 上的 Finder 和 Codex 可以读取 `iCloud Drive/VoiceContext`。用户运行 `generate-meeting-minutes` Skill，选择自己的模板，把单场会议逐字稿生成到会议目录的 `generated/` 子目录。原始逐字稿不被修改。

#### 场景 F：无 iCloud 使用

用户关闭 iCloud 或没有可用 iCloud 空间时，应用继续在本地 Documents 的同构目录工作。用户通过 Files、Share Sheet、AirDrop、存储到文件或复制文本把逐字稿交给桌面工具。

## 5. v1 目标与成功标准

### 5.1 产品目标

- 在 iPhone 15 / iOS 18 上可靠完成用户主动发起的语音记录。
- 让个人用户在不填写标题或选择类型的情况下快速记录一个念头，并能回听、阅读、编辑和导出。
- 在无网络条件下完成 VAD、SenseVoice 转写、说话人处理、编辑和本地导出。
- 生成稳定、可审计、可被 Codex 使用的 Markdown 和 JSON 文档。
- 让用户明确理解麦克风、后台录音、本地处理、iCloud 和音频保留边界。
- 提供自首次打开应用起连续 72 小时本地转写试用，以及一次性永久解锁。

### 5.2 v1 发布成功标准

- 未经用户点击开始，应用不访问麦克风。
- 录音状态始终可见，并有立即停止入口。
- 整场录音除显式记录的系统中断 gap 外没有不可解释的音频缺口。
- 后台录音不会因为 Metal 工作失败而终止。
- 回到前台后，积压 utterance 按时间顺序补齐。
- 前台正常、无积压时，已关闭的 60 秒 AudioChunk 立即开始增量处理；文稿落后录音不超过一个分片周期加本地处理时间。
- 录音与处理状态彼此独立；旧 Recording 仍在处理时，用户仍可开始新的 Recording。
- 所有公开 transcript segment 都有稳定 ID、绝对时间、录音内偏移和可追溯 speech spans。
- 跨 AudioChunk 的 transcript segment 保存全部 `source_ranges`，不把文件边界伪装成语言边界。
- iCloud 仅同步文本、结构化数据、模板和派生纪要，不同步原始音频。
- 原始音频到期删除后，逐字稿、日历记录与派生纪要仍可阅读。
- Codex Skill 不覆盖原始逐字稿，不把 suspected 说话人升级为 confirmed。
- App 不包含云端 ASR、内置 LLM 总结、订阅或服务端账号系统。

## 6. v1 范围

### 6.1 包含范围

- iPhone 15 及以上。
- iOS 18 及以上。
- 设备麦克风录音。
- 用户手动开始和停止的统一语音记录。
- 面向个人灵感、待办、复盘和口述草稿的低门槛语音记事体验；不新增独立 Recording 类型。
- 可选会议结构化字段：主题、参与人和纯文本议程。
- 锁屏或切换 App 后的后台录音延续。
- 本地 AAC-LC 音频分片。
- 本地 Silero VAD。
- 本地 SenseVoice Small `Q8_0` 转写。
- 本地 CAM++ speaker embedding 和会议内聚类。
- 用户确认式跨会议声纹档案。
- 按日历浏览的记录流与记录内片段。
- 逐字稿文本、标题、标签和说话人名称的基础纠错。
- 本地 Documents 导出。
- 可选公开 iCloud Drive 文档同步。
- 可选加密声纹档案同步。
- 自首次打开应用起连续 72 小时本地转写试用（非语音秒额度，非每日重置分钟数）。
- StoreKit 2 非消耗型永久解锁。
- `generate-meeting-minutes` Codex Skill。

### 6.2 明确不做

- iPad 专用界面或适配。
- macOS App。
- Windows App。
- 输入法或语音输入法。
- 电话录音。
- 采集其他 App 的系统音。
- 自动开机监听或未经用户明确开始的常驻录音。
- 被系统强制终止或设备重启后自动重新打开麦克风。
- 云端 ASR。
- 内置 LLM 会议纪要或日常总结。
- 订阅。
- 业务账号和业务服务器。
- 原始音频 iCloud 同步。
- 波形级手工切分、合并和时间边界编辑。
- 日常时间轴专用 Codex Skill。

## 7. 平台与运行约束

### 7.1 iOS 约束

- 后台录音只在用户明确开始后延续。
- 锁屏和切换 App 可以继续录音，但系统强制终止、设备重启或系统中断后不承诺自动恢复麦克风。
- 进入后台后不提交新的 Metal command buffer；只继续录音、VAD、分片落盘和任务排队。
- 回到前台后恢复 Metal 转写，并按录音时间顺序处理积压。
- AudioChunk 关闭、处理积压或旧 Recording 转写均不得占用当前麦克风会话；停止录音在最后 chunk 和 journal 安全关闭后立即释放采集能力。
- 电话、Siri、音频路由变化和系统中断必须产生显式 gap，不能把中断前后伪装为连续录音。

### 7.2 当前工程基线

截至本文日期，仓库已有：

- iOS 18、iPhone-only 的 SwiftUI 工程 `speech_note`。
- SwiftData 模板数据模型和基础单元/UI 测试骨架。
- iCloud/CloudKit entitlement 占位。
- 指向现有实现的 `transcribe.cpp` 目录软连接。

当前 SwiftUI 页面仍是 Xcode 模板列表，不代表本 PRD 中任何产品页面已经实现。麦克风、后台音频、模型、文档和购买能力仍需按 PM 任务逐步交付。

## 8. 信息架构

本节是 PM `#39` 低保真原型任务的直接输入。低保真原型可以优化页面组合和导航表达，但不得减少这里定义的能力和关键状态。

```text
VoiceContext
├── 首次引导
│   ├── 本地与隐私说明
│   ├── 麦克风权限
│   ├── iCloud 文本同步选择
│   ├── 加密声纹同步选择
│   └── 72 小时试用说明
│
└── 记录（唯一主页面）
    ├── 顶部：日历 / 日期切换
    ├── 当日记录流
    │   ├── 录音中 / 处理中 / 已完成 / 需要注意
    │   ├── 记录标题、时间、参与人、标签与音频保留状态
    │   └── 记录详情
    │       ├── 本地音频回听、逐字稿、文本与标签编辑
    │       ├── 说话人重命名 / 确认 / 否认
    │       ├── 导出 MD / JSON 与派生纪要状态
    │       ├── 长期保留开关
    │       └── 可选会议结构：主题、参与人、议程文本
    ├── 开始记录
    │   ├── 直接开始
    │   └── “这是一次会议”（可选）→ 主题、参与人、议程文本
    ├── 录音中 / 停止确认 / 处理中
    └── 右上角“我的”
        ├── 试用剩余时间 / 永久解锁 / 恢复购买
        ├── iCloud 文本同步与加密声纹同步
        ├── 音频保留与存储
        ├── Skill 说明、隐私说明与第三方许可
        └── 状态与错误说明
```

### 8.1 导航原则

- 全部可见记录都属于同一个日历记录流；会议不是 Tab、列表或录音类型。
- “开始记录”是唯一一级录音操作；可在开始前、进行中或结束后设为会议并补充结构化字段。
- 任一正在录音状态必须可以从当前页面直接停止。
- 用户离开录音页面后，App 内仍必须持续显示录音状态和返回入口。
- 设置收纳在右上角“我的”，不占用底部 Tab；日历与当日记录流始终是主页面。
- 处理中、完成和需要注意是不同状态，不能统一显示为“已完成”。
- 删除音频与删除逐字稿是不同操作，界面必须明确影响范围。

## 9. 核心用户流程

### 9.1 首次启动

```text
打开 App
  → 了解“本地识别、音频不上传”
  → 请求麦克风权限
      → 允许：继续
      → 拒绝：进入可浏览状态，开始录音时再次解释如何授权
  → 选择是否启用公开 iCloud 文本同步
  → 选择是否启用加密声纹档案同步
  → 了解首次打开后 72 小时免费试用
  → 进入首页
```

要求：

- 麦克风权限和 iCloud 选择应分开说明，不能让用户误以为启用 iCloud 才能录音。
- 用户关闭 iCloud 后仍能使用全部本地录音、转写、编辑和导出能力。
- 首次引导不得在用户未点击录音前启动麦克风。

### 9.2 开始与完成一条记录

```text
日历记录页
  → 开始记录
  → 直接开始录音，接住个人念头或现场对话
  → 可选在开始前或稍后勾选“这是一次会议”
      → 会议主题、参与人、议程文本（均可稍后补充）
  → 点击开始录音
  → 录音中：每约 60 秒关闭一个 AudioChunk
      → 下一 AudioChunk 立即继续采集
      → 前台立即增量处理已关闭 chunk
      → 后台只继续录音、VAD、落盘和排队
  → 用户点击停止
  → 关闭不足 60 秒的最后 AudioChunk 并立即释放麦克风
  → 剩余转写、聚类和文档任务继续处理，不阻止开始下一条 Recording
  → 完成离线重聚类和公开文档生成
  → 进入同一条记录详情，出现在当天日历流
```

要求：

- 点击开始后必须立即显示录音状态，不以模型初始化完成作为录音开始条件。
- “开始记录”应在首页首屏或固定操作区持续可达；不能要求用户先填写标题、选择记录类型或进入会议表单。
- 用户可以在开始前、进行中或结束后添加标题、参与人、标签、会议主题与议程文本。
- “这是一次会议”只增加结构化字段和会议纪要语义，不能创建不同的录音处理、详情或列表路径。
- 个人短记录默认以开始时间或首段文本提供可识别标题；这只是展示与后续编辑结果，不新增数据类型。
- 较长静音形成记录内片段；片段不是新的麦克风会话或记录对象。
- 内部 AudioChunk 不作为用户可见的录音或片段；播放、时间轴和导出仍以一条 Recording 表达。
- 普通 AudioChunk 边界不结束 utterance；尾部未完成语音以绝对样本范围形成 carry，等后续连续 chunk 可用后重组识别。
- 后台期间待处理数量可以增加，不能误报转写仍实时进行；停止后不能用空逐字稿伪装完成。

### 9.4 前后台切换

```text
前台录音与分钟级增量转写
  → 每约 60 秒关闭一个 AudioChunk，并立即创建处理检查点
  → 同时继续采集下一 AudioChunk
  → App 进入后台
  → 停止提交 Metal 工作
  → 继续录音、VAD、60 秒分片落盘、carry 保存和 utterance 排队
  → App 回到前台
  → 恢复 Metal
  → 按时间顺序补转写积压
```

要求：

- 进入后台不能中断录音。
- 后台页面状态应明确表达“录音继续，转写待回到前台处理”。
- 回到前台后应同时显示当前录音状态和待处理数量。
- 前台正常且无积压时，UI 可以表达“分钟级增量转写”或“已转写至 +MM:SS”，不得声称逐字实时。

### 9.5 修正逐字稿与说话人

```text
记录详情
  → 选择文字段或说话人
  → 修改文本、记录字段 / 重命名说话人
  → 接受或否认疑似历史人物
  → 保存
  → revision + 1
  → 从结构化数据重新生成 transcript.md
```

要求：

- suspected 与 confirmed 必须有明确的视觉和文字差异。
- 用户否认疑似身份后，该结果不能进入长期声纹档案。
- v1 不提供波形级时间边界编辑。

### 9.6 使用 Codex Skill 生成纪要

```text
标记为会议且转写 complete 的记录
  → 文本同步到 iCloud Drive/VoiceContext（或本地导出）
  → Mac Codex 读取会议目录
  → generate-meeting-minutes 校验 schema/state/revision
  → 选择默认或用户模板
  → 写入 generated/<template-slug>/<timestamp>.md
```

要求：

- `state != complete` 时 Skill 停止并说明仍有转写任务。
- JSON 存在时优先读取 JSON。
- Skill 永远不修改 `transcript.json` 或 `transcript.md`。
- 输出保留来源 recording ID、revision、template 和 generated_at。

## 11. 产品状态模型

### 11.1 录音状态

| 状态 | 含义 | 用户看到什么 | 允许的主要操作 |
|---|---|---|---|
| `idle` | 没有正在录音 | 日历记录页主入口 | 开始记录 |
| `preparing` | 正在初始化音频会话 | 短暂准备提示 | 取消 |
| `recording` | 麦克风持续采集 | 红色持续状态、时长、音频电平 | 暂停、停止 |
| `paused` | 用户主动暂停 | 暂停提示和已录时长 | 继续、停止 |
| `interrupted` | 电话/Siri/系统打断 | 明确中断和 gap 提示 | 等待恢复、停止 |
| `stopping` | 正在关闭分片和 journal | 正在安全保存 | 等待，不重复提交停止 |

### 11.2 处理状态

| 状态 | 含义 | UI 规则 |
|---|---|---|
| `recording` | 仍在录音；可同时存在已关闭 chunk 的处理任务 | 录音状态优先展示，同时显示“已转写至”与待处理数量 |
| `processing` | 有 VAD、转写、聚类或文档任务 | 显示待处理数量和当前阶段 |
| `locked_pending_purchase` | 试用已到期，utterance 保留但不转写 | 显示永久解锁入口，不删除任务 |
| `complete` | 所有必要任务完成，公开文档已原子生成 | 允许导出和 Skill 使用 |
| `needs_attention` | 有不可自动恢复的错误或冲突 | 显示原因、影响和可执行操作 |

### 11.3 说话人状态

| 状态 | 含义 | 展示规则 |
|---|---|---|
| `unknown` | 没有可靠历史身份 | 显示“说话人 N”或“未知说话人” |
| `suspected` | 达到疑似匹配条件但未经确认 | 必须显示“疑似”，不能直接显示为已确认姓名 |
| `confirmed` | 用户已明确确认 | 显示确认名称，可将合格 embedding 加入档案 |

## 12. 功能需求

### 12.1 录音与本地数据（PM `#3`）

- `FR-REC-001`：用户可以手动开始一条 Recording，并可在任意时点填写标题、标签、参与人以及可选会议主题和议程文本。
- `FR-REC-002`：录音使用 `AVAudioEngine` 采集麦克风 PCM。
- `FR-REC-003`：原始音频保存为分段 AAC-LC `.m4a`；新录音默认每 60 秒按绝对 16 kHz 样本数关闭一个 AudioChunk，停止、暂停或系统中断允许产生不足 60 秒的尾段。
- `FR-REC-004`：音频回调只执行无阻塞缓冲和落盘，不执行模型推理。
- `FR-REC-005`：活跃录音使用 append-only journal 记录分片、VAD 时间、任务和中断事件。
- `FR-REC-006`：电话、Siri、路由变化和系统中断产生显式 gap。
- `FR-REC-007`：崩溃或被终止后，重启扫描 journal 和已关闭分片，恢复为 interrupted 并继续待处理任务。
- `FR-REC-008`：低磁盘空间时停止新录音并提示用户，不静默删除任何记录的音频。
- `FR-REC-009`：所有记录的原始音频默认保留 7 天；逐字稿、日历记录和派生纪要不因音频清理而删除。
- `FR-REC-010`：用户可在任意记录或记录内片段上开启长期保留；会议标记不自动改变默认保留期限。
- `FR-REC-011`：一条用户可见 Recording 可以包含任意数量 AudioChunk；内部文件边界不创建新的 Recording，也不暴露为用户片段。
- `FR-REC-012`：相邻 AudioChunk 必须满足前一段 `end_sample ==` 后一段 `start_sample`；中断或写入失败只能通过显式 gap 表达，不能移动、复制或重叠权威音频来迁就转写边界。
- `FR-REC-013`：历史非 60 秒 AudioChunk 保持可读、可播放、可转写和可导出；60 秒是新录音默认值，不是读取端的格式假设。

### 12.2 VAD 与转写（PM `#4`）

- `FR-ASR-001`：Silero VAD 产生保留精确采样位置的 speech spans。
- `FR-ASR-002`：相邻 speech spans 按自然停顿组成目标约 3–15 秒的 utterance；有效短语音不得因不足 3 秒被丢弃，单个 utterance 硬上限为 25 秒。
- `FR-ASR-003`：每个 AudioChunk 关闭后立即创建幂等的增量处理检查点；任务先形成 utterance，再由 SenseVoice Small `Q8_0` 在设备本地逐个转写，而不是等待整条 Recording 停止或把完整 60 秒文件强制视为一次模型输入。
- `FR-ASR-004`：前台允许 Metal 推理，后台只排队，不提交新的 Metal 工作。
- `FR-ASR-005`：同一 Recording 按 AudioChunk sequence 和绝对样本时间顺序处理；回到前台后幂等补齐积压，全局 SenseVoice Metal 推理最多一个并发。
- `FR-ASR-006`：转写失败保留 utterance、错误代码和可重试状态，不生成空文本伪结果。
- `FR-ASR-007`：热状态、内存警告和低电量时允许暂停转写，音频落盘优先。
- `FR-ASR-008`：普通 AudioChunk 边界不得强制结束 utterance。chunk 尾部未完成语音保存为 carry；后续连续 chunk 关闭后，按绝对 `[start_sample, end_sample)` 从全部 `source_ranges` 解码并在内存中重组，遇到 gap、暂停或系统中断则必须终止 carry。
- `FR-ASR-009`：前台正常、无积压时，最终文稿相对语音结束的延迟目标不超过一个 60 秒分片周期加本地处理时间；后台、热暂停、购买锁定和任务积压必须如实显示，不承诺严格实时。

### 12.3 逐字稿与时间轴（PM `#5`）

- `FR-DOC-001`：每条 Recording 的公开文档遵循 `voice-context/transcript@1`；`isMeeting=true` 的 complete 记录额外可作为会议纪要输入。
- `FR-DOC-002`：每个 segment 有稳定 UUID、sequence、绝对时间、毫秒偏移、speech span 关联和一个或多个精确 `source_ranges`；跨 AudioChunk segment 不得只记录单一 `source_chunk_id`。
- `FR-DOC-003`：Markdown 由结构化数据生成，并与 JSON revision 保持一致。
- `FR-DOC-004`：用户修改文字、标题、标签或说话人后 revision 单调递增。
- `FR-DOC-005`：按日历生成的记录索引保存当天 Recording 引用，不复制完整 canonical transcript。
- `FR-DOC-006`：无 iCloud 时支持 Files、Share Sheet、AirDrop 和存储到文件。

### 12.4 说话人与声纹（PM `#6`）

- `FR-SPK-001`：CAM++ 使用约 1.5–3 秒重叠短窗生成 embedding。
- `FR-SPK-002`：过短、低能量、低质量或疑似重叠讲话窗口不用于身份学习。
- `FR-SPK-003`：录音中只显示临时会议内说话人标签。
- `FR-SPK-004`：会议结束后执行 cosine-distance 凝聚层次重聚类。
- `FR-SPK-005`：历史身份匹配同时满足 top-1 阈值和 top-1/top-2 margin 才标记 suspected。
- `FR-SPK-006`：未经用户确认的 cluster 永不更新长期声纹档案。
- `FR-SPK-007`：CAM++ 失败时保持 unknown，不使用随机 embedding。

### 12.5 iCloud 与隐私同步（PM `#7`）

- `FR-ICL-001`：用户可独立选择是否启用公开文本同步和加密声纹同步。
- `FR-ICL-002`：公开文档写入 `iCloud Drive/VoiceContext` 的 document-scope 容器。
- `FR-ICL-003`：iCloud 不可用时使用本地 Documents 同构目录，不阻塞录音和转写。
- `FR-ICL-004`：处理中 journal 不同步，只同步原子完成且带 revision 的文档。
- `FR-ICL-005`：冲突不覆盖任意一方，保留冲突副本并提示用户处理。
- `FR-ICL-006`：长期声纹档案使用 CryptoKit AES-GCM 应用层加密。
- `FR-ICL-007`：公开目录不保存明文 embedding、设备绝对路径或原始音频。

### 12.6 Codex Skill（PM `#8`）

- `FR-SKL-001`：Skill 名称固定为 `generate-meeting-minutes`。
- `FR-SKL-002`：v1 只处理单条 `isMeeting=true` 的 complete Recording 纪要，不负责通用日历记录搜索。
- `FR-SKL-003`：输入可以是会议目录、`transcript.json` 或 `transcript.md`，JSON 存在时优先。
- `FR-SKL-004`：`state != complete` 时停止。
- `FR-SKL-005`：suspected 不能写成 confirmed，不虚构决定、行动项或负责人。
- `FR-SKL-006`：输出固定写入 `generated/<template-slug>/<YYYY-MM-DD_HH-mm-ss>.md`。
- `FR-SKL-007`：Skill 不修改原始 Markdown 或 JSON。

### 12.7 试用、购买、隐私与许可（PM `#9`）

> 试用模型已于 2026-08-13 修订：由「60 分钟 ASR 语音秒」改为「首次打开起连续 72 小时」。细则与迁移见增补 PRD `FR-ADD-TRL-*`。

- `FR-BIZ-001`：试用时钟自用户**首次打开应用**进入前台时启动，持续 **72 小时**（墙上时钟）；不按提交给 SenseVoice 的语音秒累计，也不按自然日「每日额度」重置。
- `FR-BIZ-002`：试用期内与试用到期后均允许录音和保存音频；试用到期不删除已有录音或文稿。
- `FR-BIZ-003`：试用到期后新的转写任务标记为 `locked_pending_purchase`。
- `FR-BIZ-004`：永久解锁后自动继续处理积压任务。
- `FR-BIZ-005`：购买使用 StoreKit 2 非消耗型商品，支持恢复购买。
- `FR-BIZ-006`：目标价格约 ¥58，最终使用 App Store 最接近的本地价格档位。
- `FR-BIZ-007`：设置页展示 SenseVoice、transcribe.cpp、sherpa-onnx、3D-Speaker、Silero VAD 等许可与归因。
- `FR-BIZ-008`：SenseVoice 商业发布前完成 FunASR Model License 法律审核（已完成审核，允许商业使用，已在设置页完成模型与作者出处归因标注）。
- `FR-BIZ-009`：设置与锁定 CTA 展示剩余试用时分；不得再展示「剩余 60 分钟语音额度」。
- `FR-BIZ-010`：试用起点应持久化并尽量抵抗卸载重装重置（Keychain 或等价策略）；无法 100% 防刷时须在审核材料中披露限制。

## 14. 音频生命周期

| 类型 | 默认保留 | 用户可做什么 | 到期或删除后的文本 |
|---|---|---|---|
| 任意 Recording 的原始音频 | 7 天 | 播放、主动删除、将记录或片段设为长期保留 | 逐字稿、日历记录和纪要保留 |

规则：

- 自动清理只删除本地音频和设备侧音频引用。
- 删除音频前界面必须说明逐字稿不会删除。
- 原始音频不进入公开 iCloud Drive 目录。
- 低存储时不通过静默删除任何记录音频腾空间。

## 15. UX 与无障碍要求

### 15.1 录音安全感

- 录音中使用持续可见、不可与普通处理状态混淆的视觉标识。
- 停止入口在录音页直接可见，不藏在二级菜单。
- 从后台返回时，第一屏明确显示录音是否仍在继续。
- 系统中断产生 gap 时，界面显示中断时间和影响，不伪装为连续音频。
- 录音页把暂停、继续和结束集中在底部拇指可达区；个人独白时不强迫显示参与人或会议字段。

### 15.2 语音记事体验

- 首页首屏清楚表达“会议、对话或一个念头都可以记录”，并持续提供单一录音入口。
- 个人短记录和会议在日历流中使用同一种 Recording 卡片骨架，通过标题、时长、参与人和可选“会议”标记自然区分。
- 详情页以音频播放器为首要内容，提供播放、15 秒快退/快进、进度和倍速，再展示逐字稿、片段和说话人。
- 不提供内置 AI 总结、自动模板推荐或实时翻译；参考同类硬件/应用时只借鉴低门槛录音与音频优先的信息层级。

### 15.3 状态反馈

- `recording`、`processing`、`complete`、`needs_attention` 必须使用不同文案和视觉状态。
- 录音中允许同时展示分钟级增量文稿、最后已转写时间和待处理 AudioChunk 数；处理状态不能覆盖或弱化正在录音的主状态。
- 后台积压要显示“录音继续，转写待前台处理”，不能显示为实时转写。
- 试用到期不显示“录音失败”，而应说明音频已保存、转写等待解锁。
- iCloud 错误不阻塞本地功能，并明确告知文档仍保存在本机。

### 15.4 无障碍

- 支持动态字体，关键操作在最大常用字号下仍可完成。
- 主要控制满足最小触控区域要求。
- VoiceOver 能读出录音状态、已录时长、暂停/停止、待处理数量和说话人身份状态。
- 颜色不是区分 unknown/suspected/confirmed 的唯一方式。
- Reduce Motion 开启时移除非必要动画，保留状态变化信息。
- 深色模式保持录音、错误、警告和确认状态的可读对比度。

## 16. 失败与恢复要求

| 失败场景 | 产品行为 | 禁止行为 |
|---|---|---|
| App 崩溃或被终止 | 重启扫描 journal，恢复 closed chunks、carry 和待处理任务，状态标记 interrupted；未关闭 chunk 单独诊断，不伪装为已提交 | 自动重新打开麦克风，或把未确认尾段静默并入已关闭音频 |
| 设备重启 | 保留音频和任务，提示用户手动重新开始 | 后台秘密恢复录音 |
| 电话/Siri/路由变化 | 写入 gap，显示中断或路由变化 | 把前后音频拼成无 gap 的连续记录 |
| SenseVoice 失败 | 保留 utterance、错误码和重试入口 | 用空文本标记完成 |
| CAM++ 失败 | 标记 unknown | 生成随机 embedding 或伪造说话人 |
| iCloud 不可用 | 使用本地 Documents，显示同步状态 | 阻塞录音或本地转写 |
| iCloud 冲突 | 保留双方副本，提示选择 | 静默覆盖任意一方 |
| 低存储 | 停止新录音并提示清理 | 静默删除会议音频 |
| 热状态/低电量 | 暂停推理，继续音频落盘 | 为保持实时文本而牺牲录音完整性 |

## 17. 隐私、安全与合规

- 麦克风权限请求前解释用途。
- 未经用户明确点击开始，不访问麦克风。
- 录音中持续显示状态和停止入口。
- 所有 ASR、VAD 和说话人处理在设备本地执行。
- 原始音频只保留在录制设备。
- 公开 iCloud 文档不包含明文声纹 embedding。
- 长期声纹档案采用 AES-GCM 应用层加密。
- 同步密钥通过可同步 Keychain 管理。
- 设置页提供第三方许可、模型来源和作者信息。
- 商业发布前完成 SenseVoice/FunASR 模型许可法律审核。

## 18. 试用与永久解锁

### 18.1 免费试用

- 用户首次打开应用时启动 72 小时试用时钟，并在引导/设置中说明「首次打开后 72 小时内可试用」。
- 试用期内转写不按语音秒扣减。
- 已完成文档始终可以查看、编辑和导出。
- 从旧版「60 分钟语音秒」迁移规则见增补 PRD `FR-ADD-TRL-006`。

### 18.2 试用到期后

- 继续允许录音和保存音频。
- 停止新的 SenseVoice 转写。
- 新任务进入 `locked_pending_purchase`。
- 清晰告知用户音频未丢失，永久解锁后会继续处理。

### 18.3 永久解锁

- StoreKit 2 非消耗型购买。
- 目标价格约 ¥58，最终价格以 App Store 可选本地价格档位为准。
- 支持恢复购买。
- 永久解锁后自动处理锁定积压。
- 无业务服务器和产品账号系统。

## 20. 测试与发布验收

### 20.1 自动化测试

- JSON schema、RFC3339 时间、时区、毫秒偏移和 sequence 派生。
- speech spans 合并为 utterance 的边界、有效短语音、25 秒硬上限和跨 AudioChunk carry/source ranges。
- 60 秒 AudioChunk、历史非 60 秒 chunk 兼容、gap、journal/carry 恢复、音频分片完整性和幂等重试。
- 录音与转写并行时无掉包、重复样本或麦克风阻塞；停止后最后尾段立即入队且可开始新 Recording。
- 在线聚类、离线重聚类、身份阈值、top-2 margin 和确认后才更新档案。
- AES-GCM 加解密、错误密钥和同步冲突。
- 默认 7 天音频清理、任意记录长期保留与清理后文档可读。
- 72 小时试用边界、试用到期、购买恢复和解锁续跑。
- iCloud 原子写入、revision 单调递增、冲突副本和本地 fallback。
- Markdown/JSON 一致性和用户编辑后重建。
- Skill schema、模板、输出路径、来源 revision 和 suspected 保真。

### 20.2 真机验证

- iPhone 15 / iOS 18 的 30 分钟、2 小时和长时间统一记录。
- 锁屏、切换 App、电话、Siri、蓝牙断连、路由变化、低电量、发热和低存储。
- 后台没有新的 Metal 工作，回前台按时间顺序补齐。
- 前台连续录音期间，每个 60 秒 AudioChunk 关闭后立即入队；正常无积压时验证分钟级延迟、跨 chunk 句子不重不漏和全局单一 Metal 并发。
- 中文、英文、粤语和中英混合会议。
- 2、4、6 人会议、换座、远场、背景音乐、短插话和重叠讲话。
- iCloud 开启、关闭、空间不足、网络中断和 Mac 同时读取。
- Mac Codex 使用默认模板和用户模板各生成一次纪要。

### 20.3 UI/UX 验收

- PM `#41` 在 iPhone 15 / iOS 18 真机完成核心体验设计走查。
- 深色模式、动态字体、VoiceOver、Reduce Motion 和最小触控区域通过。
- 发布阻断级 UI/UX 与无障碍问题全部关闭。
- `#41` 完成后，PM `#36` 才能进入最终端到端发布验收。
