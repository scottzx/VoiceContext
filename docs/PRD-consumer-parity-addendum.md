## 1. 背景与对标结论

### 1.1 竞品呈现的用户心智

竞品商店叙事强调：

- Transform voice to text **offline**，100% on-device privacy
- Record / import audio（含视频音轨、语音备忘录分享）
- Identify different speakers
- 轻量免费额度话术（如 “5 free minutes daily”）
- 列表主路径：全部录音 + 搜索 + 大麦克风 FAB + 导入 FAB
- 导出：`.txt` / `.srt` / 音频 / Share
- 文件夹归类、桌面 Record Widget、中英 / 纯英模式切换

### 1.2 VoiceContext 已具备的差异化（无需为对标重做）

以下已在主 PRD / 现实现中成立，增补阶段应作为**优势文案**保留，而不是被竞品清单稀释：

- 分钟级增量转写与录音/处理解耦（长会议）
- 确认式跨会议声纹，而非仅单场临时分色
- 开放 Markdown / JSON + Codex `generate-meeting-minutes` Skill
- 本地优先公开文档与可选加密声纹同步
- StoreKit 2 永久解锁（非订阅）；试用策略见本增补 **§5.0 / §8：首次打开起连续 72 小时**（取代主 PRD 原稿「60 分钟语音秒」表述，主 PRD 需同步修订）

### 1.3 缺口摘要（本增补范围）

| 优先级 | 缺口 | 竞品表现 | 当前 VoiceContext |
|---|---|---|---|
| P0 | 列表逐字稿搜索 | 底部/顶部 Search transcriptions | 日历/列表浏览为主，全文检索缺失 |
| P0 | 消费级导出 | txt / srt / 音频 / Share 菜单 | 以 MD / JSON / VoiceContext 为主 |
| P0 | 导入入口扩展 | Files + Photos/视频 + Share Sheet | Files 已有；v1 补 Photos/视频抽音轨；**Share Extension 明确不做**（见 D4） |
| P1 | 文件夹/归类交互 | Move to Folder 底栏 | 缺文件夹浏览与移动；**须支持 iCloud 同步**（见 D2） |
| P1 | 语言模式开关 | ZH-EN / English Only 设置项 | 能力需显式产品化并写入设置 |
| P1 | 详情播放「播客感」 | ±10s、当前句高亮、说话人色条图例 | 播放与说话人已有，信息层级与控件需对齐 |
| P2 | 桌面录音 Widget | 主屏一键 Record | 无 |
| P2 | 主页信息架构收敛 | All Recordings + 双 FAB | 偏日历心智，新用户路径偏长 |

商业化：**已确认**改为「首次打开应用起连续 72 小时」试用（非 60 分钟语音秒，也非竞品「每日 5 分钟」）。实现需替换现有 `#34` 额度账本语义，商店文案同步改写。

## 2. 目标与非目标

### 2.1 目标

1. 让新用户在 30 秒内理解：录音、导入、搜索、导出四条主路径。
2. 导出与分享覆盖普通用户（txt/srt/音频）与进阶用户（MD/JSON/Codex）两套出口，默认不互相遮挡。
3. 导入覆盖 Files 与相册/视频音轨（**v1 不含 Share Extension**；语音备忘录可先经 Files/导出后再导入）。
4. 提供文件夹归类，并支持用户开启后的 **iCloud 同步**（与公开文档同一套冲突/空间不足语义），不另建第二套记录模型。
5. 语言模式可切换且设置内可见，商店文案与真实能力一致。
6. 用 Widget 与主页收敛支撑「闪击胶囊」冷启动。

### 2.2 非目标

- 不引入云端 ASR、账号体系或订阅。
- 不把应用改造成「自动监听」或系统通话录音。
- 不内置 LLM 总结替代 Codex Skill。
- 不采用竞品「每日 N 分钟」额度模型；v1 试用为 **首次打开起连续 72 小时**，到期后永久解锁购买。
- v1 **不做** Share Extension（见 D4）；不因此阻塞 Files / Photos 导入。
- 不要求 v1 提供完整冲突合并 UI 或跨设备音频库。
- 不要求 Android / macOS 原生客户端。

### 2.3 成功标准

- 未使用过 VoiceContext 的用户，在无讲解情况下能完成：开录 → 停止 → 打开详情播放 → 导出 txt 或分享。
- 用户可从相册视频（不限时长，见 D3）或 Files 音频导入并得到可播放、可转写的 Recording；语音备忘录 v1 经 Files 中转，不依赖 Share Extension。
- 列表搜索能在 ≥20 条记录中按文稿关键词命中目标记录。
- 商店页可诚实宣称：离线处理、说话人、Files/相册导入、txt/srt 导出、72 小时试用后永久买断；Codex/开放文档作为差异化段落单独呈现。不宣称 Share Extension，直至该能力交付。

## 3. 用户场景增补

#### 场景 G：找一条旧录音里的原话

用户记得某次讨论提过「验收标准」，在全部录音页搜索关键词，从结果进入详情并定位到对应片段附近播放。

#### 场景 H：把语音备忘录转成可编辑文稿（v1 路径）

v1 **不提供** Share Extension。用户将语音备忘录导出/存储到 Files 后，在 VoiceContext 内用「从文件导入」创建 Recording，排队转写，完成后可编辑并导出 txt/srt。Share Extension 列为 v1 之后候选项。

#### 场景 I：给视频做字幕草稿

用户从照片图库选择一段视频（**不设产品时长上限**），应用抽取音轨并转写；长视频依赖本地标准化与排队，导出 `.srt` 供剪辑工具使用。磁盘不足时遵循主 PRD 低存储停写/提示原则，不得静默丢任务。

#### 场景 J：按项目归类

用户将多条 Recording 移入「客户拜访」文件夹，之后从文件夹筛选浏览；会议标记与文件夹可并存。

#### 场景 K：主屏闪击开录

用户在主屏点 Record Widget，应用进入录音中状态（权限已授时尽量少打断）。

## 4. 信息架构与交互原则

### 4.1 主页收敛原则

主页默认呈现「全部录音」列表心智，日历条带可作为过滤而非唯一入口：

- 主操作：大号录音按钮（FAB 或等价显著控件）
- 次操作：导入（展开：文件 / 照片与视频）
- 常驻：搜索框（列表底部或顶部，与竞品同级可见）
- 辅助：文件夹入口、设置

日历日流保留，但不得阻塞「全部 + 搜索」路径。

### 4.2 导出分层原则

| 层级 | 格式 | 默认可见对象 |
|---|---|---|
| 常用 | `.txt` 纯文本、`.srt` 字幕、分享音频、系统 Share | 详情导出菜单前三项 |
| 进阶 | `transcript.md`、`transcript.json`、导出 VoiceContext 包 / Skill | 「高级导出」或「给 Codex」分组 |

不得删除 MD/JSON；仅调整信息层级。

### 4.3 文件夹与标签关系

- **文件夹**：用户可见的归类容器（浏览/筛选主路径），一条 Recording 同一时间最多属于一个用户文件夹，或「未分类」。文件夹元数据在用户开启相关同步后进入 **iCloud**（与公开文档本地优先、冲突保留副本策略一致）。
- **标签**：多值标记，继续服务主 PRD 已有纠错与文档字段。
- **会议开关**：结构化模式，不等于文件夹。

### 4.4 隐私与网络话术（商店/引导共用）

必须可验证地表述：

- 录音、VAD、转写、说话人处理在设备本地完成。
- 原始音频不进入公开 iCloud Drive。
- 无业务账号服务器。
- **网络仅用于**：App Store / StoreKit 购买与恢复；以及用户显式开启的 iCloud 文档/声纹同步。

## 5. 功能需求

编号前缀 `FR-ADD-*` 表示本增补专属需求；实现时可映射为新的 PM 任务。

### 5.0 试用与商业化修订（P0，修订主 PRD / `#34`）

> 产品负责人 2026-08-12 确认：试用改为**按天计时的 3 日试用**，不再使用「60 分钟 ASR 语音秒」总量模型。

- `FR-ADD-TRL-001`：试用期为自 **首次打开应用** 起连续 **72 小时**（墙上时钟）。起点在首次进入前台时写入持久化存储（建议 Keychain + 本地文件双写防丢）；之后不以「首次转写」重置。跨时区不重新延长试用；用户改系统时间导致异常时，以实现可检测的单调时钟 / 服务器无关策略降级（不得依赖业务服务器）。设置与引导须写明：「首次打开后 72 小时内可试用」。
- `FR-ADD-TRL-002`：试用期内，转写/导入处理**不按语音秒扣减额度**；录音可靠性与本地处理能力不受试用时钟限制以外的人工配额限制。
- `FR-ADD-TRL-003`：试用结束后，新的转写任务进入 `locked_pending_purchase`；已落盘音频与已完成文稿保留，不删除用户数据。
- `FR-ADD-TRL-004`：StoreKit 2 非消耗型永久解锁购买或恢复成功后，清除锁定并允许队列续跑（沿用 `#34` 解锁续跑行为）。
- `FR-ADD-TRL-005`：设置与锁定 CTA 文案展示剩余试用时间（优先小时+分钟，不足 1 小时显示分钟），不得再展示「剩余 60 分钟语音额度」。
- `FR-ADD-TRL-006`：从旧版「60 分钟语音秒账本」迁移：已解锁用户保持解锁；未解锁用户以迁移时写入/补写的「首次打开」时间戳起算 72 小时——若无可靠时间戳则自本次升级后首次打开起算；已超时则保持锁定待购（具体迁移表在实现说明中列出，禁止默默清空历史录音）。

**验收**：新装用户在首次打开后第 71 小时仍可转写、第 73 小时进入锁定；购买/恢复后续跑；卸载重装不得重置试用（Keychain 或等价防重置策略，若无法 100% 防重装刷试用须在审核说明中披露限制）。

### 5.1 列表搜索（P0）

- `FR-ADD-SRCH-001`：全部录音（及当前文件夹视图）提供逐字稿全文搜索入口，占位文案类似「搜索转写内容」。
- `FR-ADD-SRCH-002`：搜索范围至少包括标题、逐字稿纯文本；可选包括说话人显示名与标签。
- `FR-ADD-SRCH-003`：结果列表展示命中摘录（关键词上下文一行），点击进入详情；若可廉价实现，进入后滚动到首个命中 segment。
- `FR-ADD-SRCH-004`：无网络可用；索引可本地增量维护，不得上传文稿。
- `FR-ADD-SRCH-005`：空查询返回当前过滤下的正常列表；无命中时有明确空态。

**验收**：准备 20 条含不同关键词的文稿，搜索唯一词仅返回目标记录；杀进程重启后结果仍正确。

### 5.2 消费级导出（P0）

- `FR-ADD-EXP-001`：详情导出菜单提供「导出文本 (.txt)」，内容为可读纯文本（可含说话人标签与简单时间码，但不要求 YAML）。
- `FR-ADD-EXP-002`：提供「导出字幕 (.srt)」，时间码与 segment 起止对齐；无 segment 时禁用并说明原因。
- `FR-ADD-EXP-003`：提供「导出音频」或「分享音频」：麦克风 Recording 导出可播放拼接/原文件策略须在实现说明中写清；导入 Recording 分享私有副本。
- `FR-ADD-EXP-004`：提供系统 Share Sheet 分享上述产物之一。
- `FR-ADD-EXP-005`：MD / JSON / VoiceContext 高级导出保留，视觉上次于常用导出。
- `FR-ADD-EXP-006`：导出失败不损坏源 Recording；处理中记录可导出已完成部分或明确禁用并提示。

**验收**：同一条多人对话可导出 txt 与 srt；用外部播放器/字幕工具抽查时间轴；Share Sheet 可 AirDrop 到 Mac。

### 5.3 导入扩展（P0）

- `FR-ADD-IMP-001`：导入入口提供「文件」与「照片与视频」两项（文案可本地化）。
- `FR-ADD-IMP-002`：从照片图库选择视频时，抽取音轨生成导入 Recording，复用现有 `ImportedAudioAsset` / ProcessingRange 管线。
- `FR-ADD-IMP-003`：**v1 不做** Share Extension / 分享目标扩展；文档与引导须提供「语音备忘录 → 存储到文件 → App 内导入」说明。该能力可排入 1.0.x 候选项，不挡 v1 门禁。
- `FR-ADD-IMP-004`：不支持的格式给出可读错误，不创建半残 Recording。
- `FR-ADD-IMP-005`：导入后列表有「导入」标识；播放时间轴连续；转写与离线重聚类行为与现 `#52` 一致。
- `FR-ADD-IMP-006`：大文件/长视频导入有进度或明确排队提示，不阻塞新的麦克风录音（采集与处理解耦原则）。
- `FR-ADD-IMP-007`：**不设产品级视频时长上限**；实现必须能处理长素材（标准化、分窗、可恢复队列）。磁盘空间不足时停止扩容写入并提示，不得静默删除用户记录。

**验收**：Files m4a、相册视频（含 ≥30 分钟样例）各至少 1 条端到端成功；失败用例（损坏文件）不崩溃；无 Share Extension 不视为缺陷。

### 5.4 文件夹归类（P1）

- `FR-ADD-FLD-001`：用户可创建、重命名、删除文件夹；删除文件夹时记录回到「未分类」，不删除 Recording。
- `FR-ADD-FLD-002`：列表支持「移动到文件夹」动作（多选可选做 P1.1）。
- `FR-ADD-FLD-003`：文件夹筛选与日历过滤可组合或有清晰互斥规则（实现时写明，默认：文件夹筛选优先于「全部」）。
- `FR-ADD-FLD-004`：文件夹名出现在列表次要元数据中（可选图标）。
- `FR-ADD-FLD-005`：文件夹元数据必须支持 **iCloud 接入**：用户开启同步后，文件夹定义与 Recording→文件夹归属在设备间可见；关闭同步或 ubiquity 不可用时降级为本地同构数据，不阻塞录音/转写。
- `FR-ADD-FLD-006`：文件夹同步冲突遵循主 PRD / `#31`：不覆盖任意一方，保留冲突副本或等价 `needs_attention`，失败不阻塞本地录音。
- `FR-ADD-FLD-007`：公开 iCloud Drive 目录仍不得因文件夹同步而写入原始音频或明文声纹。

**验收**：创建设备 A 文件夹并移动记录后，在已登录同一 iCloud 且同步开启的设备 B（或二次安装）可见归属；断网/关同步时本地仍可用；制造冲突时不丢任何一侧数据。

### 5.5 语言模式（P1）

- `FR-ADD-LNG-001`：设置中提供语言模式：至少「中英双语（默认）」与「英语优先/英语 only」两档（最终命名以设计为准）。
- `FR-ADD-LNG-002`：模式影响新转写任务的模型/解码配置；已完成文稿不自动重跑，除非用户显式「重新转写」。
- `FR-ADD-LNG-003`：详情可只读展示该 Recording 使用的语言模式（若按条记录存储）。
- `FR-ADD-LNG-004`：商店与引导文案必须与真实可选模式一致，禁止宣传未实现模式。

**验收**：切换模式后新录音/新导入任务行为可区分；旧文稿不被静默改写。

### 5.6 详情播放与说话人呈现（P1）

- `FR-ADD-PLY-001`：详情播放器提供约 ±10 秒跳转（或现有跳转改文案对齐习惯）。
- `FR-ADD-PLY-002`：播放时高亮当前 segment；列表式说话人色条/图例在检测到 ≥2 说话人时可见。
- `FR-ADD-PLY-003`：标题区可展示时长、创建时间、语言标签（如 ZH-EN）等元数据，避免信息过载。
- `FR-ADD-PLY-004`：遵循既有无障碍要求（Dynamic Type、VoiceOver 标签、Reduce Motion）。

**验收**：纳入 `#41` 走查清单增补项；双说话人样例可见图例且高亮跟随播放头。

### 5.7 主屏录音 Widget（P2）

- `FR-ADD-WDG-001`：提供可安装的主屏 Widget，主操作启动/继续录音（具体为 deep link 开录或打开开始表，以实现选简单可靠者为准）。
- `FR-ADD-WDG-002`：未授麦克风权限时，点击后进入应用内权限说明，不静默失败。
- `FR-ADD-WDG-003`：Widget 不展示逐字稿隐私内容。

**验收**：安装 Widget 后可冷启动进入录音流程；无权限路径可恢复。

### 5.8 主页信息架构（P2，可与 P0 搜索/导入同批做）

- `FR-ADD-IA-001`：默认首页突出全部录音列表、搜索、录音主按钮、导入入口。
- `FR-ADD-IA-002`：日历过滤降为列表上方工具，不作为唯一首页。
- `FR-ADD-IA-003`：设计需更新 `docs/design/v1/` 对应说明，并通过一次轻量走查（可附在 `#41`）。
