## 1. 目标

允许用户从 iPhone 的 Files 中选择已有音频，导入 VoiceContext，并在设备本地完成按范围处理、排队、转写、播放、编辑和导出。

用户不需要重新播放音频或通过 App 内录音“转录一遍”。导入的文件应和麦克风录音一样成为一个用户可见的 Recording，并进入同一套首页列表、详情页、统一时间轴和转写任务队列。

## 2. 用户场景

- 用户已有会议录音、采访音频或语音备忘录，想在本 App 内离线转写。
- 用户从 Files 选择一个音频文件，等待本地转写完成，同时可以离开详情页。
- 用户重新打开已导入记录，查看处理进度、回听音频、编辑文本并导出。
- 用户导入失败或转写失败时，原始音频仍保留，可以重新处理。

## 3. 范围

### 本次包含

- 通过系统 Files picker 选择音频文件。
- 将源文件安全复制到 App 私有目录，不修改 Files 中的原文件。
- 校验音频是否可读取，并提取时长、采样率、声道、文件大小等元数据。
- 在转写时按需将所需范围解码为 16 kHz、单声道 PCM，不把整段音频一次性读入内存。
- 默认每 60 秒建立一个逻辑 `ProcessingRange`；它记录时间或采样点边界，不生成新的 60 秒 PCM/AAC 文件，也不暴露为多个用户记录。
- 每个 `ProcessingRange` 创建一个独立转写任务。
- 复用 VAD、跨片续接、SenseVoice、本地文稿和失败重试机制。
- 在首页按导入时间显示一条 Recording，并标识“导入音频”来源。
- 详情页提供统一播放时间轴、转写文本、处理状态和导出入口。

### 本次不包含

- 视频文件导入和从视频提取音频；作为后续扩展，不在本需求中默认承诺。
- 云端转写、账号上传或第三方音频服务。
- 翻译、摘要或自动会议纪要；本次口述中的“翻译”已确认是“转写”。
- 自动删除用户在 Files 中的原文件。
- 自动去重或跨设备同步导入音频。

## 4. 用户流程

```text
首页
  → 点击导入
  → 系统 Files picker
  → 选择音频
  → 显示导入校验与文件信息
      → 不支持/损坏：说明原因，保留首页，不创建半成品记录
      → 可读取：创建 Recording，复制到私有目录
  → 建立连续的 60 秒逻辑处理范围
  → 每个处理范围进入转写队列，并按需读取源文件
  → 详情页显示“导入中 / 转写中 / 已完成 / 需要注意”
  → 播放、查看文本、编辑、导出
```

## 5. 状态与错误

### 导入状态

- `选择中`：系统文件选择器打开。
- `校验中`：读取文件格式与元数据。
- `导入中`：复制源文件、读取元数据或建立逻辑处理范围。
- `已导入，等待转写`：音频已安全落盘，任务尚未开始。
- `转写中`：至少一个分片正在处理，后续分片可排队。
- `已完成`：所有必要任务完成，文稿可读。
- `需要注意`：导入、音频解码或转写失败；原始音频和已完成部分保留，可重试。

### 错误文案要求

- 不支持格式：说明“无法读取此音频格式”，不要泛化为“转写失败”。
- 文件损坏：说明“音频文件无法读取，原文件未被修改”。
- 存储空间不足：说明需要释放空间，并保留已有数据。
- 转写失败：显示具体分片或任务状态，允许重试，不伪造完成。
- App 进入后台：保留待处理任务，回到前台后继续；不丢失已完成分片。

## 6. 数据与处理约束

### Recording

建议为 Recording 增加来源元数据：

- `origin`: `microphone` 或 `importedAudio`。
- `sourceFilename`: 用户选择的原始文件名，仅用于显示和导出元数据。
- `sourceUTType`: 通过系统 Uniform Type Identifier 记录原始类型。

原始文件名不能代替稳定的 Recording ID。导入后由 Recording ID、`ImportedAudioAsset`、`ProcessingRange` 和任务 ID 建立关联。

### ImportedAudioAsset 与 ProcessingRange

- `ImportedAudioAsset`：App 私有目录中唯一的完整源文件副本，是播放、重新处理和媒体导出的权威来源。
- `ProcessingRange`：以 `sequence`、`startSample/startTime`、`endSample/endTime` 描述的可持久化处理单元，默认 60 秒；它不是媒体文件。
- 处理某个范围时，只从源文件读取该范围所需音频，并在内存中规范化后执行 VAD。VAD 仍按既有规则形成短 utterance；跨范围未闭合语音沿用续接标记处理。
- 仅当原始编码无法稳定随机读取或解码时，允许生成**一份**标准化私有媒体资产；后续仍使用逻辑处理范围，不生成多个 60 秒文件。

### 音频

- Files 原文件复制到 App 私有目录后，App 只读取副本。
- 原文件不上传、不写入公开 iCloud 文档目录。
- 播放直接使用完整源文件（或唯一标准化资产）组成统一时间轴；用户不需要看到处理范围或分片按钮。
- 逻辑处理范围的边界以绝对样本位置记录，避免格式转换或重试造成时间跳变。

### 转写任务

- 新导入记录不得创建 `chunk_id = NULL` 的旧版整段任务。
- 一个 `ProcessingRange` 对应一个可重试的范围任务，稳定任务键包含 `recordingID + processingRangeID + pipelineVersion`。
- 跨分片语音需要下一片时保留续接状态；成功后清除关联标记。
- 任务和文稿写入必须幂等，App 被杀后不能重复生成文本段。
- 录音采集和导入处理互不占用对方的麦克风会话。

## 7. UI/UX 要求

沿用 `DESIGN.md` 的“安静的原生工具”方向：原生 Files picker、扁平记录列表、单一播放器控制面和清晰的处理状态，不增加卡片堆叠、渐变或装饰性 AI 面板。

最低页面状态：

- 导入入口：使用明确的“导入音频”文字和 Files 图标。
- 导入中：显示文件名、时长、已建立处理范围数量和当前状态。
- 转写中：显示已完成范围 / 总范围，以及可继续离开页面的提示。
- 完成：播放器优先，文稿随后；来源文件名作为次级元数据。
- 失败：显示失败原因和“重新处理”，不隐藏音频。
- VoiceOver：导入按钮、文件名、导入状态、转写进度、播放控制和失败操作均有明确标签。
- Dynamic Type：长文件名、错误说明和进度文本可换行，不截断关键状态。

## 8. 验收标准

- 用户可以从 Files 选择一个受支持音频并创建一条 Recording。
- 原始 Files 文件保持不变，App 私有副本可读取。
- 60 秒以上音频按 60 秒边界建立多个逻辑处理范围，首页仍只显示一条记录；默认只保留一份完整私有媒体文件。
- 每个处理范围都有独立任务，停止或重启不会产生整段重复任务。
- 转写在设备本地完成；断网不影响导入、播放和转写。
- 详情页可以统一播放导入音频，支持播放/暂停、±15 秒、拖动和速率调整。
- 转写完成后可以编辑并导出文本；失败时可以重试。
- App 在后台或被系统终止后重新打开，已完成范围不重复处理，未完成范围继续排队。
- 原始音频不进入公开同步目录，文稿和音频保留策略与麦克风录音一致。
- 真机至少验证：20 秒、81 秒、5 分钟音频；中文普通话、包含静音、跨 60 秒边界语音和不可读取文件。

## 9. 待确认项

- 首批明确支持的音频格式清单，以 iPhone 15 / iOS 18 真机解码矩阵为准。
- 单个导入文件的时长和大小上限。
- 导入音频是否消耗现有免费转写额度，以及按文件时长还是处理时长计费。
- 导入完成后是否立即自动开始转写，还是由用户在详情页点击“开始转写”。
- 是否在后续版本支持视频导入并提取音频。
- 是否允许用户在导入后修改语言模式或重新选择中文/英文模型。
