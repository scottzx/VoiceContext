## 30 分钟后台连续性

1. 显式点击开始，确认界面立即显示录音中。
2. 锁屏、切换其他 App，累计保持至少 30 分钟。
3. 从锁屏/控制中心使用停止入口；若系统未展示入口，记录截图和复现步骤并回到 App 停止。
4. 导出所有 AAC chunk，运行完整性诊断。

通过条件：chunk UUID 唯一；16 kHz mono AAC 可逐个播放；样本边界连续；任何缺口都有对应 gap；后台期间未提交新的 Metal 转写工作。

## 2 小时分片

1. 连续录制 2 小时，期间至少经历一次锁屏和一次前后台切换。
2. 停止后核对约 5 分钟一个 chunk；最后一段允许不足 5 分钟。
3. 汇总 chunk 的 `startSample/endSample`，确认无重叠、无未解释缺口、总时长与墙钟时间偏差可解释。

## 中断与路由

- 电话或 Siri 打断：记录 gap 的起止时间、样本位置和 UI `interrupted` 状态。
- 蓝牙断连/路由变化：确认产生显式 route gap 或点状诊断事件。
- 中断结束后：确认 UI 与 journal 同步恢复；不允许把中断前后伪装成无 gap 连续音频。

## 强制终止与恢复

1. 录音中强制终止 App。
2. 重启后确认 Recording 为 `interrupted`，已关闭 chunk 可见且可播放。
3. 确认运行中的 job 回到 `pending`，重复启动不会重复创建 Recording、chunk、gap 或 job。
4. 必须由用户显式继续或停止，不能重启后秘密打开麦克风。

## 低存储与保留

- 低于保护阈值时：新录音在请求麦克风前被拒绝，并显示明确原因。
- 所有 Recording（包括会议）原始音频默认 7 天；会议标记不自动延长。
- Recording pin 或 chunk pin 后不得清理相应音频。
- 清理只删除到期且未 pin 的音频；逐字稿、日历索引和派生文档必须保留。
- 不允许为了低存储静默删除尚未到期的音频。
