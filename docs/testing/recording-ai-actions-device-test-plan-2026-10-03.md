# 一芥伙伴开发版真机测试方案

日期：2026-10-03。测试对象：本次安装到 iPhone 15 Pro 的 Yima Dev（一芥伙伴开发版），版本 1.0 (7)。本方案用于验收一键录音、标题编辑、回听定位和录音可靠性，并记录原生界面体验。当前已完成构建、签名和安装；以下真机用例均待执行。

建议先做第一轮，约 20–30 分钟，转写等待时间另计。第一轮通过后再补权限、后台和多人场景。测试结果填写“通过 / 失败 / 阻塞 / 未测”；没有合适样本或权限时记录阻塞，不能计作通过。

## 测试前准备

1. 打开手机上的 Yima Dev，进入“会议”。如果出现试用到期、购买或模型加载错误，先截图并记录阻塞原因；不要为测试购买商品、卸载应用或清空数据。
2. 使用新建的测试录音，命名为“反馈验收 A”等。准备约 3 分钟的自然讲话，每隔一段读一个容易辨认的标记，例如“第一段，今天讨论测试”“第二段，先把标题改名做好”“第三段，接下来检查播放定位”“第四段，测试结束”。记录大致说话时间。
3. 给麦克风授权；先在红键下方选择“个人记录”。选择类型后应保持未录音，随后再点红键。首次默认类型只在没有保存过偏好的安装中验证，不通过重置现有数据制造首次状态。
4. 等待这条测试录音有足够逐字稿，再做文字定位用例。两个以上发言人和文字缺口用例需要对应样本，可放到第二轮。
5. 每项记下结果及录音名称。需要录屏时保持系统录屏麦克风关闭，录制操作画面即可。

## 第一轮核心体验

按表中顺序执行，尽量复用同一条测试录音。

| 用例 | 操作 | 通过标准 |
|---|---|---|
| C01 一键开始 | 在“会议”点击一次红键，讲话约 3 分钟 | 已有麦克风权限时，不再弹类型或地点选择；录音状态和计时出现。停止后仅新增一条录音，能回听开头、中间和结尾的标记 |
| C02 类型记忆 | 点红键下方类型，选“多人会议”；观察是否开录，再点击红键录一小段。停止后退出并重新打开 App | 选类型只改变下次类型，不开始采集；重新打开后仍记住选择。红键按所选类型开录。多人模式不等于已实时确认真人身份 |
| C03 暂停继续与跨页 | 录音时切到聊天、待办、拓展，再回录音；暂停，等 5 秒，继续说最后一句后停止 | 其他页可找到录音状态及停止入口；切页前后的讲话都在同一条录音。暂停期间不采集，继续后恢复；暂停时长不要求计入音频时长 |
| C04 点击标题保存 | 打开“反馈验收 A”详情，直接点标题，改成“反馈验收 A 已改名”并保存；返回列表，再打开详情，最后重开 App | 出现原生编辑 Sheet；关闭后详情立即显示新标题，列表和再次打开的详情一致，重开仍保留；音频及正文没有变化 |
| C05 取消标题编辑 | 点标题，输入另一个名称后取消 | 详情、列表和重开后的名称都保留原值 |
| C06 暂停时拖进度条 | 在逐字稿页保持播放器暂停，分别拖到第一、第三个讲话标记内部，再点快进或快退 15 秒 | 音频位置变化但仍暂停；有真实文字区间时，当前句高亮并滚入可见范围。定位按播放器实际时间；不可播放的音频缺口可能跳到下一可播位置 |
| C07 播放中拖动 | 播放测试录音，拖到较后的一段，再快退 15 秒 | 从新位置继续播放，文字位置与正在听到的句子对应；不反复跳回拖动前的位置 |
| C08 手动阅读与恢复 | 播放时手动向上翻到较早文字，等下一句开始，再点底部“跟随播放位置” | 手动阅读期间不被自动拉回；恢复入口始终在底部可操作。点击后回到当前句，后续重新跟随 |
| C09 同句再次定位 | 暂停并定位某句；手动翻走，再把进度条拖到同一句内部的另一个时间点 | 即使句子未变，也能重新滚回该句，不被上一次定位缓存挡住 |
| C10 不打断其他页 | 切到详情“备忘录”或“详细信息”，拖动播放器，再返回逐字稿 | 不自动切换详情页、不丢失备忘录输入；回逐字稿后可用手动拖动或恢复跟随定位 |

C01–C03 可以合并做一条约 3 分钟的录音；C04–C10 复用该录音。结束后再新录 10 秒，确认 App 仍能开始和停止下一条录音。

## 第二轮权限与可靠性

| 用例 | 操作 | 通过标准 |
|---|---|---|
| R01 连续点击 | 未录音时快速连点红键；若出现系统麦克风询问，完成授权后查看录音列表 | 只启动一次采集，不重复弹权限，不出现虚假的“已有会话”失败，不产生多条录音 |
| R02 拒绝与恢复麦克风 | 在 iPhone 系统设置关闭开发版麦克风权限；回 App 点击录音，再从失败提示进入系统设置恢复权限，返回重新点击录音 | 拒绝时显示可理解的失败原因，不冒充正在录音；恢复后能正常开录，已有录音仍可浏览。结束后恢复测试前的权限设置 |
| R03 地点开关 | 在“拓展 → 设置 → 录音相关设置 → 隐私与权限”找到“录音时自动记录地点”；分别关闭、开启并授权，再新录一条 | 关闭时不获取地点；开启时可异步填写，录音不等待地址。拒绝定位仍能录音；详情点击标题可手工修改地点。取址失败或地址不准要单独记录 |
| R04 锁屏与后台 | 新录一条，每约 20 秒读一个标记；中途锁屏约 1 分钟，再解锁回 App 停止，回听所有标记 | 后台前后的讲话完整可回听，状态与计时一致；返回不新建另一条录音。后台文字处理可能等待前台，不把它误判为录音丢失 |
| R05 长录音 | 第一轮通过后录 15–30 分钟，期间切页、锁屏，开始、中间、结束各读标记 | 能停止、保存、回听三个位置并再次开始新录音；无无故停止、卡死或丢内容。记录发热、电量变化和结束后等待全文的时长 |
| R06 改字后重试 | 在测试稿某句长按，选择“编辑此句逐字稿…”，写入明显的校对标记；再用更多菜单“重新转写 / 分析”，完成后重开详情 | 人工校对内容保留；不把空或部分识别结果覆盖成整份空稿；失败有提示，旧稿仍可读 |
| R07 追录 | 对已停止的测试录音，使用更多菜单“增录音频…”追加一小段并停止 | 原音频与原稿保留，追加内容属于同一条录音；随后能重新开始另一条录音。启动失败时不一直卡在活动状态 |
| R08 无网络 | 结束正在进行的采集，开启飞行模式并关闭 Wi-Fi，录一段、停止、回听并查看本地转写 | 本地录音与回听可用；本地转写在资源和使用权限正常时继续工作，不要求配置云模型密钥；完成后恢复连接设置 |

页面文案会随语言改变，设置路径以实际“录音”分组为准。麦克风权限修改放在第一轮录音结束后进行。存储写入失败和追录等待竞争已有主机检查，真实设备故障注入另由工程测试准备；不用填满手机空间或删除应用文件来制造这些错误。

## 多人文字与原生界面

| 用例 | 操作 | 通过标准 |
|---|---|---|
| U01 发言人过滤 | 用两人轮流讲话的测试录音，待处理后筛选一个发言人；拖到另一个人的发言，再点“跟随播放位置” | 筛选保留时不滚向隐藏句，也不误指向其他发言；恢复时显示全部并定位当前句。未产生可用分组时先记录说话人问题，本项阻塞 |
| U02 没有对应文字 | 用已经确认存在文字覆盖缺口的样本，拖到缺口或逐字稿末尾之后的音频 | 不高亮或定位上一句来冒充当前句；音频可继续播放。没有确认过的缺口样本则记未测；一段静音不一定就是文字覆盖缺口 |
| U03 深浅色与大字 | 在 App 切换深浅色，在 iPhone 调大辅助功能字号；重复标题编辑、录音和恢复跟随 | 标题可换行，Sheet 保存/取消及播放器不被遮挡，按钮可点，重要状态可读；横向溢出、截断或颜色不符规范均记录 |
| U04 VoiceOver 与减少动态效果 | 开启 VoiceOver 操作标题编辑、播放、拖动时间轴、恢复跟随；开启减少动态效果后再次操作 | 控件有准确名称、可完成同等动作；减少动态效果后仍能定位而不依赖位移动画。记录详情标题、播放器、逐字稿的朗读顺序 |
| U05 二级页面导航 | 从会议列表和搜索结果分别进入录音详情；进入聊天详情、待办“全部”、拓展的 Skills / 模型与服务 / 浏览器及更深页面；分别用返回按钮、侧滑返回，侧滑中途取消；打开设置并关闭 | 四个一级页显示主底部导航，二级及更深页面隐藏；返回一级页随转场恢复，取消侧滑仍隐藏；关闭设置后恢复之前页面的导航状态。录音详情播放器仍可操作，搜索高亮与定位保留 |

界面检查沿用 [DESIGN.md](../../DESIGN.md)。当前已知说话人紫色配色、句卡片着色和底部播放器的阅读顺序仍需核对；测试中记录这些差异，不把既有差异计作这批新增逻辑已经修复。

## 记录速度与识别质量

用同一份测试音频记录下列结果。当前没有已批准的延迟或准确率目标，先建立基线，不凭主观感觉写“性能通过”。

- 首字等待：开始讲话到第一批文字出现，约多少秒。
- 持续滞后：讲话过程中，屏幕最新文字比实际讲话落后约多少秒；至少观察 3 次。
- 停止后就绪：点击停止到整份逐字稿可用，多少秒；没有就绪时写实际等待时长及页面状态。
- 核对关键词：事先写下约 20 个要点，包括姓名、日期、数字、否定词等；逐项记正确、错误或漏掉，保留音频依据。这是要点核对结果，不等同于字错误率。
- 多人识别：分别记录声音有没有分开、哪一轮归错、是否把未知身份当真人姓名；不要用手工改名后的结果算自动识别准确率。

## 判定与反馈

第一轮全部通过，才能说明本批基础路径在这台设备上可用。第二轮和界面用例按实际完成情况报告，不宣称完整录音 AI 闭环、全部性能或所有设备已经验收。新的“整理对白”、直接在录音内发起 AI 整理、持久行动确认等仍未交付，本次不把网页演示当 App 功能测试。

遇到丢音频、原稿被覆盖、无法停止录音或持续崩溃，记为 P0，暂停后续涉及该数据的操作并保留样本；核心操作失败但数据可回读记为 P1；文案、间距和颜色等体验问题记为 P2。不确定原因时记录现象，不需要自行排查内部文件。

```text
实际：____
出现次数：3 次中出现 __ 次

```

汇总记录：第一轮通过 __ / 10，失败 __，阻塞 __；第二轮通过 __ / 8，失败 __，阻塞 __；多人与界面通过 __ / 5，失败 __，阻塞 __。恢复改动过的系统权限、网络和辅助功能设置后，再确认可以新录一条并回听。
