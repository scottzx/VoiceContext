# CRM 首版可点击 H5 原型

设计依据：[CRM 首版设计](../crm-local-first.md)与[项目设计规范](../../../DESIGN.md)。用户于 2026-10-16 明确授权制作原型并沿用现有风格；规范适用范围与确认记录见主设计第 11 节。

原型入口：[index.html](./index.html)。页面为独立 HTML/CSS/JavaScript，无构建依赖，可直接用浏览器打开；使用本地服务可获得更一致的预览体验。

```sh
python3 -m http.server 4186 --bind 127.0.0.1 --directory docs/design
```

打开 [本机预览](http://127.0.0.1:4186/crm-local-first-prototype/)。这是运行服务的电脑上的地址，不能直接作为其他设备的访问地址。

## 本轮评审范围

- **CRM 首页**：公司、客户、商机三个主入口，以及待跟进、下一次约见、最近往来摘要；“查看全部”打开预设 CRM 范围的共用列表。
- **客户详情**：基本资料、公司与通讯录绑定状态、相关商机、下一步、将来安排和往来入口。
- **商机详情**：参与人、阶段、需求、金额/预计日期、跟进任务与往来；未知值不伪造。
- **往来时间轴**：按实际往来日期分组，切换全部/沟通/图片；查看选定纪要、沟通及图片资料，保留返回上下文。

页面使用系统字体、黑白灰、平铺行和原生风格表单。电脑上左侧为手机画布，右侧为评审快捷入口；窄屏直接适配浏览器宽度。右侧工具是原型评审环境，不属于产品页面。2026-10-17 新增“全部个人待办”“会议资料”对照入口，验证不同入口使用同一条记录和同一个详情。

## 建议点击路径

1. 首页 → 客户 → 林知远 → 查看关联公司与商机 → 打开“客户服务流程优化”。
2. 商机详情 → 查看/更新阶段 → 新建跟进任务 → 返回客户查看同一任务 → 完成任务 → 返回首页核对待办变化。
3. 客户详情 → 往来 → 筛选沟通 → 打开会议纪要 → 返回原时间轴；同一纪要关联多位客户仍只有一条活动。
4. 往来 → 图片 → 预览示例资料；新增图片时可从电脑或手机浏览器文件选择器选图，填写往来说明和时间。
5. 添加沟通 → 手工记录，或选择已有纪要 → 核对归属并确认 → 在当前客户/商机时间轴查看。
6. 从右侧快捷入口切换四个重点页面，切换深浅色、重置演示，并检查键盘焦点和窄屏排版。
7. 首页待跟进 → 查看全部 → 范围切到“全部个人待办”：可见独立的读书笔记事项；在这里完成客户任务，返回 CRM 首页核对同一结果。
8. 公司/客户/商机 → 全部待办：预设当前业务范围；查看已完成待办并进入详情，返回后范围和完成筛选保留。
9. 首页最近往来 → 查看全部 → 选择商机并筛选沟通 → 打开纪要 → 查看关联沟通 → 返回，保持范围、类型筛选和滚动位置。

## 演示数据与边界

`seed.js` 提供虚构公司“禾序科技”、客户“林知远 / 陈映”、两个商机、任务、日程和往来资料。演示当天固定为 2026-10-16，未完成任务和将来日程分别呈现。示例图片为本地 SVG 业务资料，明确标注演示，不冒充真实客户照片或附件。

2026-10-17 增加一条没有公司/客户/商机关联的个人待办。它只出现在全部个人范围中；原业务待办、日程、纪要与图片仍使用原有 ID 和同一组数据。范围切换只筛选展示，不复制数据或创建事项。

修改保存在本次页面内存中，刷新或重置后恢复；选择的本机图片只用于浏览器预览，不上传服务器。页面不调用实际通讯录、EventKit、照片库同步、消息系统或模型，也不迁移真实客户数据。通讯录与系统来源状态仅展示设计示例；message 为 P2，本轮不提供消息接入。

H5 中的图片选择器用于验证选图与确认流程，正式 iOS 版本仍按设计使用系统照片选择器。表单、任务完成、来源详情与纪要选择均是原型交互，不代表系统事项已经创建、真实通知已经配置或原生工具已接通。

## 验证记录

2026-10-16 验证结果：

- `node --check`、演示实体/图片引用、SVG 格式及文档相对链接检查通过。
- Edge 浏览器实际点击走通客户 → 商机 → 往来 → 沟通 → 会议纪要 → 返回；返回保留时间轴筛选。
- 实际输入并保存一条无期限跟进任务，客户页立即出现；完成后从未完成列表移除。修改原任务标题保留既有 18:00 时间和原参与客户。
- 商机阶段从方案/报价改为沟通中后更新；手工沟通经核对确认后在客户往来中出现。
- 示例图片可打开预览，Escape 关闭并把焦点交回原图片按钮；查看纪要、沟通/图片筛选均有实际行为。
- 393×852 与 320×740 CSS 视口的重点页面没有横向溢出，已检查的产品按钮命中区域至少 44×44；755 px 布局切换无横向溢出。已保存深浅色与电脑预览截图。
- 未观察到页面 JavaScript 异常；浏览器扩展有自身 `chrome-extension://invalid/` 错误，与本原型脚本分开记录。

自动化选取本机图片受 BrowserSkill 的浏览器文件访问权限限制，未完成真实文件附着验证，未修改浏览器权限。选择器、图片加载与内存归档流程已实现，实际本机选图、多选和取消仍需手动走查；不将示例图片预览等同于选图导入验收。

2026-10-17 调整核对：

- 首页只保留三个实体入口；共用待办支持 CRM、全部个人、公司、客户、商机范围和完成状态。
- 实际在全部个人范围完成“发出流程优化方案初稿”，CRM 范围与首页立即移除该未完成项；“整理本周读书笔记”未进入 CRM 范围。
- 公司页进入全部待办默认选中公司；改选林知远并查看已完成事项后，进入详情再返回保留选择与完成筛选。
- 商机范围的往来列表仅展示对应活动；沟通类型不显示独立图片记录。
- 从往来打开沟通和纪要，再使用纪要中的关联沟通入口返回，最终恢复同一商机范围、沟通筛选及原 178.5 px 滚动位置。
- 新的范围选择器及按钮在 320 px 宽度下无横向溢出，已检查命中区域至少 44×44。
- 改选全部个人范围后返回首页，再次从首页“查看全部”进入时重新预设 CRM 范围；详情返回则保留用户先前筛选。
- 会议资料对照入口与 CRM 沟通打开同一个 `minutes:meeting-review`，标题、文稿版本和正文一致；未观察到本原型 JavaScript 异常。
