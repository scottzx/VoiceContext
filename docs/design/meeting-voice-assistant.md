# 会议录音中的语音助手

## 范围与依据

- 状态：首版实施；用户于 2026-10-11 明确选择会议录音中通过关键词调用现有 Agent，并要求 TTS 回复。
- 目标：录音继续，用户说“小蓝同学＋指令”，助手取得本场已转写内容，调用现有工具，口头接单并报告真实结果。
- 首批演示：查询待办/日程、按明确要求创建待办、整理本场已记录的事项。复用现有工具及权限，不扩展新的业务工具。
- 不做：独立长聊、全天后台唤醒、声纹认证、任意跨应用读取、第二条麦克风采集链。

### 2026-10-11 本地声学唤醒增补（用户已确认）

用户实测“小蓝同学”被 ASR 写为同音的“小兰同学”，导致文字精确匹配漏唤醒。改为随 App 预装 Sherpa-ONNX 中文 KWS 模型，直接嵌入工程；不增加模型下载操作，不改变现有转写模型安装清单。

实现顺序与验收：

1. 固定官方模型、中文发音词表、许可及 SHA-256，独立资源目录随包复制 → 构建产物离线完整性检查。
2. 唯一录音引擎的 16 kHz 单声道 PCM 扇出至有界串行 KWS worker → 推理不阻塞音频 tap 或写盘，不创建第二个麦克风采集器。
3. 命中后立即在现有对话中显示“已唤醒，正在听”；Silero VAD 收尾，支持同句指令及 8 秒内继续说话 → 独立有界指令 PCM 转写，无需等待会议长分片。空唤醒、超时及过长指令不执行工具。
4. 请求继续进入原 Agent / answer_user / TTS → 宿主测试覆盖去重、暂停/后台/录音切换、播报尾音和迟到回调；通用 iPhone 编译通过。真机声音与录音连续性由用户手动验收。

唤醒以声音命中为准，指令 ASR 不再负责授权唤醒。若保留关键词用于避免漏首字，转写只清除开头“小蓝同学／小兰同学”；没有声学命中的会议文字不能提交任务。KWS、VAD、ASR 全部本地运行；Agent 仅接收明确指令和已提交的会议上下文。短提示音复用录音播放能力且不会插入新的 TTS 句子打断用户。

仅实际外放期间及 0.5 秒尾音抑制唤醒；合成等待不算外放。暂停、后台、关闭、忙碌或换会议立即使旧 worker generation 失效。界面沿用已批准的原生状态文字及对话弹窗，不制作新原型。

本次本地 PM 看板仍无法连接 127.0.0.1:38080；先维护此设计与验收记录，不伪造项目项编号或发布日期。

### 2026-10-12 会话连续性与录音展示增补（用户已确认）

用户已手动跑通基础功能，并提供顶部录音横幅遮挡完整聊天的截图。本轮采用以下约定：

1. 融合应用的全局录音状态改为贴屏幕边缘的轻微系统红辉光；人讲话时随现有输入电平轻微变化，助理实际 TTS 播放时改为系统蓝色并跟随播放器输出电平。使用原生 SwiftUI，不引入第二路收音；合成等待、执行任务和短提示音不算助理回答。移除挤占聊天导航的顶部横幅，通过原生录音菜单保留状态、时长、积压、返回录音和停止操作。开启“减弱动态效果”时显示静态边缘。
2. 同一录音 ID 的所有唤醒任务使用一个 Agent 会话。开关、暂停和前后台变化不另建会话；新录音独立。原任务仍在运行时不给同一会话强行提交新任务或取消旧任务。
3. 会议转写按绝对采样时间组织为一分钟资料分片，保留正在进行的分钟内已经提交的段落。当前语音命令作为独立用户消息；会议标题、录音 ID 和开始时间明确标明当前会议。智能体无需再次查询“当前在哪场会议”才能理解本场指令。
4. 每次明确唤醒时将尚未注入的转写追加到既有会话上下文，已注入段落只发送更正或删除，不重复整份文稿。使用稳定段 ID，允许晚到的旧分钟段落；文稿暂不可用不等于删除。资料通过既有隐藏上下文机制持久化，不在用户聊天气泡展示大段 JSON 或字面换行符。普通转写更新不启动 Agent 或授权写操作。

验收：宿主测试覆盖同录音会话复用、新录音隔离、分钟边界、增量/更正/晚到/暂缺文稿以及忙碌保护；通用 iPhone 编译验证 UI 与模块装配；视觉动效与连续追问由用户在真机手动检查。

### 2026-10-12 总管分工与红蓝状态增补（用户已确认）

人讲话显示红色录音边缘，助理实际回答显示蓝色边缘；蓝色动效读取 TTS 播放器电平，避免被麦克风收到的外放回声驱动。主助手保持对话和记忆连续，承担理解、分派、追问及结果交付；复杂执行工作交给子智能体。主助手不再拥有 iSH、浏览器或文件工具，简短原生 Apple/Yima 事项请求可直接处理。

子任务异步完成后必须回到同一主会话，用新的有效 `answer_user` 绑定交付结果；关闭、暂停或后台后的旧回复不得复活。普通聊天与子智能体执行工具保持现有分工。

## 用户流程与设计

1. 用户开始会议录音，在当前录音详情开启“会中助手”。默认关闭，每场单独启用；成功开启后立即通过现有 TTS 播报“我已入会，有事叫小蓝同学”。此固定准备提示不创建 Agent 任务，静音或播报失败保留文字提示。
2. 页面说明唤醒词及“说完稍作停顿”；普通发言继续作为会议文稿。
3. 预装 KWS 直接监听同一录音 PCM，命中后显示“已唤醒，正在听”并播放短提示音；Silero VAD 收集指令并收尾，独立转写有界音频。关键词与请求可一句说完，也允许关键词后 8 秒内开始说请求。无需等待会议录音分片关闭。
4. 请求交给本场录音固定的 Agent 会话，增量追加本场资料后再提交当前指令，TTS 简短确认接单；页面显示指令、真实执行状态、最近结果和完整对话入口。主助手回合及播报期间一次处理一条指令；复杂任务分派后结束该回合、恢复待命，用户可以继续唤起追问。子任务完成后再回到本场会话交付结果，避免重复分派或重复写入。
5. 点击“小蓝同学”打开当前会议的原生对话弹窗，实时显示已收到的明确指令、接单状态、公开回复和错误。弹窗不展示模型思考或普通输出，也不新增另一种输入方式；完整任务对话入口保留。
6. Agent 必须调用专用 `answer_user(text)` 工具交付公开答复，该工具自动触发 TTS。普通模型文字和思考内容不能自动播报。每个主助手回合只交付一次工具答复；接单回合和子任务完成回合分别绑定独立回复资格，失败、超时和权限拒绝如实呈现。
7. 关闭助手、暂停/中断录音、离开前台或结束录音时停止接收新指令和当前播报；已提交任务在原聊天中保留，不伪报取消成功。

### UI/UX 风格确认

复用已批准的 `DESIGN.md`（2026-08-03 及当前增补），适用章节为 Aesthetic Direction、Typography、Color、Core Components、Motion and Haptics、Accessibility。用户要求复用现有能力；首版仅在录音详情控制区增加原生中性开关、状态及结果入口，不增加新页面结构或原型。

保持安静、原生、明确、内容优先；开关和普通按钮使用中性色，红色继续表示录音/停止。状态有文字，操作目标至少 44 pt，支持动态字体、深色模式及 VoiceOver。实现后静态走查这些状态；视觉和无障碍运行验收等待真机授权。

## 技术方案与边界

- 复用唯一的 `AACSegmentRecorder`、Silero VAD、SenseVoice 和已提交文稿。现有 AAC 分片写盘和文稿转写保持原流程；在能量门控前，将带绝对样本位置的 16 kHz PCM 分流到独立串行 KWS worker，待处理样本限制为 1 秒。溢出只丢弃助手分析输入并重置授权，不阻塞写盘。
- 唤醒直接来自声学 KWS；会议文稿只提供上下文，提交或重转写文稿不能再次触发任务。录音 ID、generation、绝对采样边界隔离启用前、暂停、后台、播报期间和迟到事件。
- 助手边界包含已入队但尚未写入的采集包，并保留一包及转换器余量；不在主线程等待写入队列。跨启用/恢复边界的整句会被保守排除，开启后稍作停顿再说指令。
- 唤醒词固定“小蓝同学”，预装 Zipformer zh-en 3M chunk-8 int8 模型，以 phone+ppinyin 发音序列匹配；不依赖 ASR 选用“蓝”或“兰”。近期 PCM 缓存 3 秒供延迟命中回滚，VAD 停止检测后约 0.7 秒收尾，8 秒内未开始有效指令则超时；超过 20 秒的指令整体拒绝，不执行截断的半句话。
- Agent 入口复用 `IOSAgentSessionRunner`，每场录音固定一个会话，沿用现有模型、工具和权限及既有会话记忆。转写按分钟增量追加为资料，不能升级为工具指令；当前命令作为独立消息，保留 recordingID 和来源位置。
- `answer_user` 仅暴露给会中助手会话，绑定当前请求及会话；关闭、过期或无绑定时拒绝交付。工具答复先显示文字，再进行有界 TTS；即使静音或合成失败，也不能因此重复业务操作。固定准备/接单/运行错误提示由宿主管理，模型普通输出不作为工具答复兜底。会中会话关闭通用自动朗读路径。
- 会中主助手固定为总管模式，保留任务分派/查询/修正/停止、`apple_native`、`yima_items`、记忆和 `answer_user` 专用工具；注册与执行两处拒绝 shell、浏览器、文件等调用。网页、脚本、文件及多步工作以子智能体执行为主。子智能体保留执行能力，只向主助手回报；主助手在分派时传入明确授权、必要分钟的会议证据和验收标准。普通聊天模式不变，会中入口不使用简化模式。
- `apple_native` 使用结构化命令、操作和逐项参数，直接复用现有 Apple 原生实现及权限检查；不经过 iSH 或 shell。只允许日程、提醒、定位、路线查询、天气及设备信息的有限操作，不提供麦克风、播放或打开浏览器操作。
- 子任务回执只表示已开始；完成通知先预留本场会议回复资格，再注入原会话，由主助手核对实际结果后调用 `answer_user`。后台结果回合不插入新的用户消息或重复“收到”。主会话忙碌时通知等待；暂停、关闭、后台或换录音使旧播报授权失效，恢复前台不会自动播出旧结果，新的明确指令接单后才重新授权后续回复。
- 准备播报拥有独立生命周期 ID；连续重复设置开启不重复播报，重新关闭再开启可再次提示。公开消息记录仅保存在本场界面内存中，换录音清空；工具会话继续沿用原聊天存储。
- TTS 复用已配置的 Voice Output。音频协调增加会议助手专用播报意图；融合录音从开始即使用可同时采集和播放的 profile，其他聊天采集/媒体/麦克风工具继续被录音所有权阻止。播报开始和结束不切换录音 profile，不暂停录音引擎。
- 仅实际播放前才进入播报抑制，结束后再保留 0.5 秒尾音；抑制期间停止 KWS 并使旧代失效，避免自身入会句再次唤醒。远程合成等待可被新声学唤醒取消，迟到合成包不能播放。此版本不支持实际播报中语音打断，提供停止播报操作。
- 播报合成等待上限 30 秒、整段播报上限 90 秒；停止、静音或失败保留文字结果。显式会中助手不依赖聊天的自动朗读开关，但尊重已有临时静音设置。
- 录音页承载现有工具权限请求，权限检查不可绕过。模型未配置、实时转写关闭或本地模型未就绪时说明原因。

## 数据、隐私与恢复

原音频与文稿沿用现有生命周期。只有显式启用后的唤醒指令及本场已提交文字进入 Agent；本地录音/ASR不新增持续云端上传。Agent/TTS 按用户已有模型配置处理请求。助手外放声音可能进入会议录音；页面提示此行为。任务会话和结果留在原聊天存储中，不另建任务数据库。

仅前台支持新指令。后台、锁定、暂停和中断状态停止唤醒，恢复后从当前采样位置重新建立边界，不回放历史指令。执行中的任务可在完整聊天中检查；结果超时或无法确认时不得自动再次创建事项。

## 验收标准

- [ ] 普通会议发言不会提交任务；关闭、历史文稿、重复结果及迟到转写不会提交任务。
- [ ] 支持同句声学唤醒、关键词单独成句及 8 秒内后续指令；等待超时后普通会议讲话不被当作请求。
- [ ] 指令携带本场上下文及来源，调用已有待办/日程工具；执行和工具权限在录音界面可见。
- [ ] TTS 使用现有配置，播报不会夺走录音所有权；自身播报不会再次触发任务。
- [ ] 明确展示收到、执行中、结果、失败和未配置状态，能打开完整对话。
- [ ] 开关开启即播报固定入会句；点击“小蓝同学”可实时核对指令和公开答复，弹窗不展示思考及普通模型输出。
- [ ] 只有有效会中请求的 `answer_user` 能交付模型答复；重复、迟到、关闭后的工具调用不重复播报，普通模型输出不进入 TTS。
- [ ] 顶部录音横幅不再遮挡聊天；人讲话红色、助理实际播放蓝色，动效分别跟随输入/输出电平，原生停止入口和“减弱动态效果”符合约定。
- [ ] 会中主助手只使用专用工具，网页/脚本/文件任务由子智能体执行；Apple 原生调用保留权限且不经过 iSH。
- [ ] 子任务完成回到本场主会话，通过新绑定的 answer_user 播报；正在收取语音指令时通知等待，旧授权失效后不复活。
- [ ] 同一录音连续任务在一个会话内，关闭再开启及暂停恢复仍保留记忆；新录音不混入旧会议。
- [ ] 按分钟增量注入已提交转写，重复快照不重复追加，晚到段落和更正不丢失，当前指令不混入历史资料。
- [x] 宿主逻辑测试、融合装配检查和通用 iPhone 编译通过，不使用模拟器。
- [ ] 用户手动在真机验证录音连续性、唤醒延迟、工具执行、TTS 共存、路由/系统中断和无障碍。

## 交付与追踪

### 真机演示步骤（由用户手动执行）

1. 打开“一芥伙伴 Dev”，保持前台和亮屏，调高手机媒体音量。拓展 → 设置 → 录音与我的设置 → 转写：确认“语音转文字模型”已就绪，打开“录音时实时转写”。确认已有可用聊天模型；MiniMax Speech 2.8 HD/Turbo 只负责播报。拓展 → 模型与服务 → 模型分组 → 默认设置 → 语音输出：选择含 MiniMax Speech 的分组；若尚无分组，先新建分组并加入对应模型。没有云端语音输出选择时使用系统语音。
2. 提醒 → ＋ → 新增会议安排，标题填“小蓝会中助手验收”，保存后重新打开该会议，点“开始会议录音”。在录音详情打开“会中助手”，无需说口令，应听到“我已入会，有事叫小蓝同学”；若静音、合成失败或超时，页面和弹窗显示对应提示。使用此已验证的会议入口，避免开始个人录音。
3. 点“小蓝同学”打开对话弹窗。入会播报结束后先正常说“录音开始测试”，再说“小蓝同学，查一下我接下来有什么日程”，说完停顿 2–3 秒。喊出唤醒词后应先看到“已唤醒，正在听”并听到短提示音，随后弹窗显示识别出的指令和接单状态；听到“收到，正在执行。”。核对工具权限提示和最终公开答复；答复通过 `answer_user` 自动播报，模型思考、计划及普通输出不应播出。弹窗打开时权限请求也应可处理。
4. TTS 播报时继续说“播报期间录音测试”，播报结束后说“录音结束测试”。结束录音后回听，确认三段测试讲话都存在且无异常断音；静音裁剪造成的时长缩短不能单独用来判断掉音。
5. 再测试写入：“小蓝同学，帮我创建一条 Yima 待办，标题是会中助手验收一号，不设置日期和提醒。”说完停顿 2–3 秒，只说一次，等待结果；如有工具权限提示，核对请求后允许本次会话。完成录音后，在提醒 → 全部 → 未安排中核对仅有一条对应待办；筛选需包含“Yima待办 · 仅本机”。通过“查看对话”核对真实工具回执。暂停、后台恢复和重复转写不能自动再次创建。实际响应时延及声音路由以真机观察为准。
