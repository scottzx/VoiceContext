# 会议录音中的语音助手

## 范围与依据

- 状态：首版实施；用户于 2026-10-11 明确选择会议录音中通过关键词调用现有 Agent，并要求 TTS 回复。
- 目标：录音继续，用户说“小蓝同学＋指令”，助手取得本场已转写内容，调用现有工具，口头接单并报告真实结果。
- 首批演示：查询待办/日程、按明确要求创建待办、整理本场已记录的事项。复用现有工具及权限，不扩展新的业务工具。
- 不做：独立长聊、全天后台唤醒、声纹认证、任意跨应用读取、第二条麦克风采集链。

## 用户流程与设计

1. 用户开始会议录音，在当前录音详情开启“会中助手”。默认关闭，每场单独启用。
2. 页面说明唤醒词及“说完稍作停顿”；普通发言继续作为会议文稿。
3. 既有分片经过 VAD 和本地 ASR 后，只解析启用后的新增发言。关键词与请求可一句说完，也允许关键词后短暂停顿再说请求。
4. 请求交给独立 Agent 会话，TTS 简短确认接单；页面显示指令、真实执行状态、最近结果和完整对话入口。一次执行一条任务，完成前不接受新的唤起，避免会议中的重复请求产生多次写入。
5. 执行结束后通过 TTS 回复，较长内容留在对话中；失败、超时和权限拒绝如实呈现。
6. 关闭助手、暂停/中断录音、离开前台或结束录音时停止接收新指令和当前播报；已提交任务在原聊天中保留，不伪报取消成功。

### UI/UX 风格确认

复用已批准的 `DESIGN.md`（2026-08-03 及当前增补），适用章节为 Aesthetic Direction、Typography、Color、Core Components、Motion and Haptics、Accessibility。用户要求复用现有能力；首版仅在录音详情控制区增加原生中性开关、状态及结果入口，不增加新页面结构或原型。

保持安静、原生、明确、内容优先；开关和普通按钮使用中性色，红色继续表示录音/停止。状态有文字，操作目标至少 44 pt，支持动态字体、深色模式及 VoiceOver。实现后静态走查这些状态；视觉和无障碍运行验收等待真机授权。

## 技术方案与边界

- 复用唯一的 `AACSegmentRecorder`、Silero VAD、SenseVoice 和已提交文稿。录音低于现有音量阈值约 1.2 秒会关闭分片并立即排队；60 秒是连续语音的硬边界。不承诺固定响应时延，积压、模型推理和长发言会延迟接单。
- 在成功转写结果提交后分流新增句子，使用录音 ID、分片 ID、绝对采样位置去重；启用时记住当前采样位置，拒绝旧积压、重转写、暂停期间及迟到结果。
- 助手边界包含已入队但尚未写入的采集包，并保留一包及转换器余量；不在主线程等待写入队列。跨启用/恢复边界的整句会被保守排除，开启后稍作停顿再说指令。
- 唤醒词固定“小蓝同学”，兼容识别文本中的标点和空白；有限支持跨句/分片匹配与短时等待后续请求。没有关键词的会议内容不提交为任务。
- Agent 入口复用 `IOSAgentSessionRunner`，每条指令单独会话，沿用现有模型、工具和权限；会议文字作为资料，不能升级为工具指令。当前命令单独标明，保留 recordingID 和来源位置。
- TTS 复用已配置的 Voice Output。音频协调增加会议助手专用播报意图；融合录音从开始即使用可同时采集和播放的 profile，其他聊天采集/媒体/麦克风工具继续被录音所有权阻止。播报开始和结束不切换录音 profile，不暂停录音引擎。
- 播报期间记录绝对采样范围；与该范围重叠的转写不得再次触发指令，避免助手自我唤醒。此首版不支持播报中语音打断，提供停止播报操作。
- 播报合成等待上限 30 秒、整段播报上限 90 秒；停止、静音或失败保留文字结果。显式会中助手不依赖聊天的自动朗读开关，但尊重已有临时静音设置。
- 录音页承载现有工具权限请求，权限检查不可绕过。模型未配置、实时转写关闭或本地模型未就绪时说明原因。

## 数据、隐私与恢复

原音频与文稿沿用现有生命周期。只有显式启用后的唤醒指令及本场已提交文字进入 Agent；本地录音/ASR不新增持续云端上传。Agent/TTS 按用户已有模型配置处理请求。助手外放声音可能进入会议录音；页面提示此行为。任务会话和结果留在原聊天存储中，不另建任务数据库。

仅前台支持新指令。后台、锁定、暂停和中断状态停止唤醒，恢复后从当前采样位置重新建立边界，不回放历史指令。执行中的任务可在完整聊天中检查；结果超时或无法确认时不得自动再次创建事项。

## 验收标准

- [ ] 普通会议发言不会提交任务；关闭、历史文稿、重复结果及迟到转写不会提交任务。
- [ ] 支持同句唤醒、关键词单独成句、跨分片关键词；等待超时后普通会议讲话不被当作请求。
- [ ] 指令携带本场上下文及来源，调用已有待办/日程工具；执行和工具权限在录音界面可见。
- [ ] TTS 使用现有配置，播报不会夺走录音所有权；自身播报不会再次触发任务。
- [ ] 明确展示收到、执行中、结果、失败和未配置状态，能打开完整对话。
- [ ] 宿主逻辑测试、融合装配检查和通用 iPhone 编译通过，不使用模拟器。
- [ ] 获得另行授权后，在真机验证录音连续性、唤醒延迟、工具执行、TTS 共存、路由/系统中断和无障碍。

## 交付与追踪

### 真机演示步骤（待授权后执行）

1. 准备可用聊天模型与 TTS 配置，在录音设置下载本地转写模型并启用实时转写。
2. 开始一场会议录音，在录音详情打开“会中助手”，稍作停顿。
3. 先正常讨论一个事项，再说“小蓝同学，把刚才确定的事项建成待办”；等待接单、工具权限提示和真实结果播报。
4. 再说“小蓝同学，查一下我接下来有什么日程”；在完整对话和提醒页面核对工具记录及条目。
5. 检查录音能继续保存；播报、暂停、后台恢复和重复转写不能自动再次创建事项。实际响应时延及声音路由以真机观察为准。
