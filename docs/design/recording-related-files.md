## 背景与问题

会议录音通常与会议通知、议程、演示文档和参考资料共同存在。当前录音详情只管理音频与转写，用户无法把多个相关文件归入同一条 Recording，导出时也要逐个分享 txt、srt、音频或高级文档。

本设计取代 `docs/design/v1/user-flows.md` 与 `docs/design/v1/design-system.md` 中“议程不接受附件、v1 不设计实体附件”的旧限制；其他既有流程和视觉规范继续有效。

## 目标

- 在录音详情关联多个来自 Files 的相关文件，并私有复制到该录音的本地目录。
- 显示文件名、类型、大小和添加时间，支持打开、系统分享和确认删除。
- 导出一个资料包 ZIP，默认包含转写文档和相关文件。
- 是否包含原始录音由全局设置控制，默认关闭。
- 录音删除、低存储、重名、导出取消和失败都有明确、一致的生命周期。

## 不做

- 不解析、搜索或总结附件内容。
- 不在 App 内编辑附件。
- 不做附件云同步、多人协作或自动关联会议。
- 不把附件直接暴露给 Codex Skill；后续如需读取，另行设计授权边界。
- 不在第一阶段改变现有单文件 txt/srt/audio/Markdown/JSON 分享入口。

## 用户、场景或调用方

- 用户进入一条录音详情，把 Files 中的会议通知、PDF、Word、图片或表格关联进来。
- 用户会前先建立资料、会后补充文件，多个文件按添加时间展示。
- 用户导出会议资料包给同事；默认包较小，需要完整归档时在全局设置开启原始音频。
- 存储层、录音删除流程和导出器共同管理附件的引用与实际文件。

## 产品流程 / 信息架构

### 添加与管理

1. 录音详情新增“相关文件”区块，显示文件数量和“添加文件”操作。
2. 使用系统 Files picker，允许多选普通文件类型。
3. App 获取 security-scoped 临时访问后，把每个文件复制到该 Recording 私有目录，再结束外部访问。
4. 列表行轻点使用系统预览或分享；更多菜单提供分享与删除。
5. 删除单个相关文件需确认，只删除 App 的私有副本，不修改 Files 原文件。

### 导出资料包

1. 录音详情的导出页保留现有单项导出。
2. 增加“导出资料包 (.zip)”。
3. 默认加入可用的 transcript.txt、transcript.srt、transcript.md、transcript.json 和全部相关文件。
4. 读取全局设置“资料包包含原始录音”；默认关闭，开启后加入合并后的原始音频。
5. 准备完成后进入系统分享；导出临时文件在分享结束或下次清理时删除。

### 全局设置

- 在设置的导出相关区域增加 Toggle：“资料包包含原始录音”。
- 辅助说明：“会显著增加压缩包大小和准备时间。”
- 设置只影响之后生成的新 ZIP，不回写既有导出文件。

## UI/UX 风格确认

- 状态：已确认，复用仓库根目录 `DESIGN.md`。
- 一句话记忆点：相关资料自然地属于这条录音，而不是另一个文件管理器。
- 风格关键词：原生、克制、文件感、可预期、低干扰。
- 反向关键词：网格素材库、彩色文件卡片、云盘式复杂导航、AI 装饰、不可逆快捷删除。
- 原生与品牌：优先 Section、List row、Menu、fileImporter、ShareLink/Share Sheet 与系统文档预览。
- 信息密度与层级：详情区块显示有限元数据；文件名优先，类型/大小/时间为辅助信息。
- 视觉方向：系统字体和文件类型图标；不按扩展名生成任意品牌色；处理中使用真实进度或不确定 ProgressView。
- 无障碍底线：动态字体、VoiceOver 文件名/类型/大小、44pt 操作区、删除确认、深色模式和 Reduce Motion。
- 决策记录：用户于 2026-08-26 确认相关文件、ZIP 默认内容及全局原音频开关。
- 既有规范：`DESIGN.md`；旧版附件禁令由本文明确覆盖。

## 原型与 UI/UX

不单独制作新原型。详情 Section、Files picker、设置 Toggle 和系统分享均为现有导航中的原生模式；实现前在设计文档确定信息架构，实现后用 Preview、UI 测试和真机走查验证空、加载、复制中、失败、多文件、长文件名、删除确认和导出大文件状态。

## 技术方案

### 目录

```text
RecordingAttachments/<recording-id>/
  index.json
  files/
    <attachment-id>.<preserved-extension>

ExportStaging/<recording-id>/<export-id>/
  <sanitized-title>.zip
```

- 实际保存名使用 attachment UUID，避免同名覆盖；界面和 ZIP 内使用原始文件名。
- ZIP 内重名文件增加稳定后缀，如 `议程 (2).pdf`。
- 复制和索引更新使用 staging + 原子替换，禁止索引指向未完成文件。

### ZIP

- 使用支持普通 Deflate/Store 的本地 ZIP writer；不得复用当前仅支持读取 ZIP_STORED 的 extractor。
- 逐文件流式写入，避免把音频或附件整体读入内存。
- 导出前估算源文件总大小并检查可用空间；包含原音频时给出更保守的空间余量。
- ZIP 只包含当前可用文档；不可用格式在导出结果说明中列出，不因非关键格式缺失阻止其余内容导出。

## 数据与接口

附件元数据至少包括：

- `id`、`recordingID`
- `originalFilename`
- `relativePath`
- `utTypeIdentifier`
- `fileSize`
- `addedAt`
- 可选 `contentHash`，仅用于导入幂等判断，不用于跨录音去重删除

新增存储接口覆盖 list/add/remove/url；调用方不得持久保存外部 security-scoped URL。

全局设置键使用明确、版本稳定的布尔值，例如 `exportPackageIncludesOriginalAudio`，默认 `false`。

删除 Recording 时，先按现有事务/日志语义标记删除，再移除对应附件目录和导出临时目录；清理失败可在恢复时重试。

## 状态、错误与恢复

- 空状态：显示“暂无相关文件”和添加入口，不显示错误样式。
- 复制中：禁用重复提交并显示正在添加的文件数。
- 单文件失败：已成功文件保留，失败文件逐项报告；不会留下索引孤儿。
- 同一来源重复选择：允许保存为两个独立附件，或通过内容哈希提示已存在；首版采用允许重复、名称自动区分。
- 文件被 App 外部删除不适用，因为使用私有副本；若磁盘损坏导致缺失，列表标记不可用并允许移除记录。
- ZIP 取消或失败：删除未完成 staging 文件，不影响附件和转写源文件。
- 空间不足：开始前阻止并说明所需空间；写入途中 ENOSPC 仍执行清理。
- 原始录音已按保留策略删除：即使全局设置开启，也导出其他内容并提示“原始录音不可用”。

## 隐私、安全与合规

- Files 访问只在用户选择后发生，复制完成即结束 security-scoped access。
- 附件保存在 App 私有目录，不自动上传 iCloud 公共文档目录。
- 文件名用于 UI 和 ZIP 前需清理路径分隔符，防止 ZIP 路径穿越。
- 删除只影响 App 私有副本，并在确认文案中明确不删除 Files 原文件。
- ZIP 可能包含敏感会议材料；分享前文案提示用户由系统分享目标决定后续去向。

## 验收标准

- [ ] 一条 Recording 可通过 Files picker 一次选择并关联多个文件，原文件不被移动或修改。
- [ ] 详情页支持空态、列表、打开/预览、分享和确认删除，长文件名与动态字体可用。
- [ ] 附件复制和索引原子提交，强杀或空间不足不会产生可见半文件或悬空索引。
- [ ] ZIP 默认包含可用转写文档和全部相关文件，默认不含原始音频。
- [ ] 全局设置开启后，新生成 ZIP 尝试包含原始音频；音频不可用时其余内容仍可导出并有提示。
- [ ] ZIP 流式生成，大附件不整体驻留内存；取消和失败清除 staging。
- [ ] 删除 Recording 后相关文件和临时导出可恢复清理。
- [ ] 旧 Recording 与旧导出流程保持兼容，不要求迁移附件数据。
