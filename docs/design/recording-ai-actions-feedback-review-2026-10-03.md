## 1. 反馈小本本

| 编号 | 反馈 / 场景 | 当前处理判断 |
|---|---|---|
| FB01 | 下载搜索找不到，安装至少约 5 分钟 | 分发与首次安装问题；核对搜索词、发布渠道、实际包体与安装步骤，原型不能证明已解决 |
| FB02 | 希望直接点击标题改名 | 现有标题接入已有录音信息编辑器；无需另造编辑页 |
| FB03 | 相比钉钉，实时转写较慢 | 记录为用户感受，需实测首字、持续落后时长和停止后全文完成耗时 |
| FB04 | 文字识别不够准确 | 保留原文、回听和校对；识别质量需用同份音频评估，不能用润色遮盖错误 |
| FB05 | 多人发言没有实时区分，发言人不准确 | 分开显示文字进度、声音区分进度与身份确认；不把临时说话人编号当真人姓名 |
| FB06 | 拖进度条，逐字稿不跟随 | 暂停拖动也应定位当前句；保留手动阅读与恢复跟随入口 |
| FB07 | 参会者偶尔看实时逐字稿，需要事后找细节，不一定写纪要 | 增加“整理对白”用途；保留轮次、时间、原意与原文回跳 |
| FB08 | 会议秘书需要快速写会议纪要 | 保留“会议纪要”用途，区分讨论、决定、行动与未决项；结果在手机可读、可修改、可分享 |
| FB09 | 不想了解存储分片、唯一标识等技术信息 | 普通阅读页移出这些字段；保留录音时长、实际空间/保留期限、缺失和失败等有用信息 |
| FB10 | 地点希望自动获取 | 现有代码已可选异步获取地点；完善权限、关闭与失败体验，不新增开录前必填地点步骤 |
| FB11 | 开始录音希望快捷，不要点两次 | 红键直接按默认/上次选择模式开始；模式切换成为次级操作，首次必要麦克风权限仍保留 |
| FB12 | AI 要跳浏览器申请服务商账号，再复制密钥到 App；即使只填一次也不愿意 | 这是使用门槛；配置次数减少不能消除注册、理解密钥、费用和失败恢复成本 |
| FB13 | 可能选择豆包、钉钉听记；已有大厂产品也能线下录音与整理 | 定位不只靠“线下录音”或“实时转写”；与竞品差异需由完整使用价值验证 |
| FB14 | 线下讨论的细节如果没录下来，事后无法回忆；部分秘书仍用录音笔 | 保留便捷、可靠捕获；考虑已有录音导入，再整理与找回细节，复用现有导入路径 |
| FB15 | 录音识别 + AI 整理 + 自动进入知识库更完整 | 先连通录音、整理结果、搜索找回与导出；完整知识库和外部自动写入是新增范围，需明确目标系统与授权 |
| FB16 | 转到电脑用 WorkBuddy 体验断节，甚至可能改用系统录音再转过去；手机直接完成更好 | 手机闭环是主要路径；电脑用于继续编辑/归档，不能成为生成纪要的必需步骤 |
| FB17 | 笔记 App 用几次就闲置，长期使用 Apple 的记录工具或 WPS；重视多端同一应用与云同步 | 降低记录与找回成本；明确哪些资料能在其他端读取、编辑、同步与删除，不只展示一个“已同步”标签 |
| FB18 | 讨论中提到 90% 与 95% 的准确率、Token 成本与备案困难 | 均为讨论中的估计/团队约束表述，不作为准确率基线、成本结论或法律判断；需要时另行核实 |

“第一批用户愿意提需求、共同改进”记录为探索背景，不把自嘲性评价当产品结论。

## 2. 两种明确用途与定位建议

**建议验证的核心用途：把线下谈话或已有录音，变成能回看细节、能交付整理稿、能再次找回的个人资料。** 这是根据反馈作出的定位假设，未替换 DESIGN.md 已批准的 Personal Agent 定位，也未验证市场需求规模。

| 使用者 | 需要什么 | 整理后的内容 | 不应牺牲的东西 |
|---|---|---|---|
| 参会者 / 需要细节的人 | 会中偶尔扫逐字稿，会后查具体对白 | 按话题分段的整理对白，保留发言轮次、时间与原意 | 不强迫浓缩成纪要；不丢限定条件、争论和不同意见 |
| 秘书 / 纪要撰写者 | 尽快形成可交付初稿 | 摘要、讨论、明确决定、行动建议、未决问题 | 不编造身份、决定、负责人或日期；保留核对依据 |

“整理对白”是本次新增候选需求，当前原型/typed 契约没有这一结果类型。建议首版只轻度去口水词、断句和明确错字，保持可回原句；存在疑义时保留并提示核对。是否合并轮次、允许何种润色、采用独立类型还是现有模板，需在实现前明确。原始逐字稿与人工校对始终保留，AI 整理稿不替换 canonical 原文。

实时逐字稿仍然有用，反馈没有支持删除它；但当前速度与多人识别不能靠画出流畅原型改善，也不能作为已胜过竞品的宣传依据。

## 3. 对当前原型的逐项审阅与最小调整

UI/UX 风格沿用已批准 [DESIGN.md](../../DESIGN.md) 的 quiet native utility：系统字体、平面文档、黑白灰、红色录音控制、原生 Sheet；保留四个主 Tab、详情四个内容页与底部播放器。复用已有风格，不启动品牌/导航重设计。

| 优先序 | 当前原型 / 实际已有情况 | 下一版调整 | 复用落点 |
|---|---|---|---|
| P0 基础体验 | 原型 record、编辑名称和选句仅显示占位说明；实际红键先弹处理模式选择 | 红键一按进入录音状态；完整演示暂停、停止、跨 Tab 录音条；点击标题编辑并同步列表名称 | Home captureDock、RecordingCoreModel.start、现有元信息编辑 Sheet |
| P0 回听 | 原型播放条为装饰；实际 Slider/±15 秒/倍速/播放跟随已存在，但 scrollToActiveSegment 要求 isPlaying | 可拖时间轴、当前句定位、高亮；暂停 seek 也定位；手动看其他段时不不断抢滚动，提供恢复跟随 | 既有 timelinePlayer、句时间范围与 ScrollViewReader |
| P0 易懂 | 原型默认展示固定版本、校验/提交、运行等较多技术过程；分片/UUID 已不在原型普通详情，但实际 App 详细信息仍有 | 常用文案改“使用当前已保存文字”“正在整理”“文字已更新”；版本号、对象 ID、技术日志收进诊断/来源详情 | 现有详情进度区、详细信息与结果 Sheet；不丢失缺口/来源更新提示 |
| P0 诚实进度 | “正在录音并实时转写”容易让用户误以为即时完成，多人结果尚未明确 | 分别展示已转写到哪个时间、剩余文字处理、正在区分声音/身份待确认；队列结束不冒充内容完整 | 实际 processing ranges/jobs、现有说话人页；不造百分比或人名 |
| P0 整理价值 | Sheet 目前仅纪要/行动/导图，且常规路径必须准备聊天草稿再发送 | 首先提供“整理对白 / 会议纪要”两个用途，并各自展示真实示例结构；保留模板、范围和高级指令 | 同一整理 Sheet、原 Agent 执行、文件/来源预览；新对白契约待定义 |
| P0 手机闭环 | 已在手机内部聊天执行，但常规整理要理解模型、聊天草稿与发送；结果入口叫“智能体产物” | 推荐普通路径为“选择用途 → 明确开始整理 → 本录音查看结果”；聊天用于调整复杂要求。前台可用“整理结果”文案，仍复用原产物 Sheet | 复用 ChatStore/执行器，不另建 Agent；直接发起需补真实消息/运行关联和发送授权，不把预填当执行 |
| P0 首次 AI | 无模型场景只提供配置入口；未演示普通用户如何设置与回到任务 | 首次云整理先展示价值、所需账号/密钥及服务商费用，提供示例和“稍后设置”；设置后回原请求，勿重复选录音/范围 | 拓展 → 模型与服务、现有 provider 配置；录音/本地转写不受阻 |
| P0 地点细节 | 实际 start 已在开录后按用户开关异步取地点 | 展示自动记录成功、未开启、失败及手动改正；定位不挡录音，拒绝定位仍能用 | LocationAccess 与已有地点字段；不偷偷请求权限 |
| P1 找回 / 跨端 | 现有搜索、公开文稿、相关文件和 iCloud 能力不等于完整知识库；整理请求/确认关联当前提案仅本机 | 在录音上下文找回原文/对白/纪要；分享/开放文稿让电脑接续。完整跨端检索、编辑、冲突与删除语义需单独设计 | 现有搜索、文件、同步与聊天引用，不加第五 Tab，不强推外部工具 |
| 分发 / 性能 | 下载困难、安装慢、识别慢与准确率差不能靠原型修复 | 作为独立缺陷/评测输入，列出实际设备、版本、音频与渠道；优化前后用同份样本比较 | 发布链路、模型资源、原 ASR/说话人处理路径 |

普通整理的推荐主路径是本次反馈驱动的新提案；当前可点击网页仍演示上一版“聊天草稿 → 发送”流程。本文没有把推荐流程写成已实现或已批准。继续调整原型时，以此表为差异清单，保留此前候选/行动确认/回执/删除分支。

结束录音后可提供“整理对白 / 生成纪要”的快捷入口，由用户明确点击开始；不默认自动联网发送。用户反馈中的“自动整理”若进一步落为开关，需要明确开启方式、发送服务、范围、费用、失败与撤销行为。仍沿用 [原 PRD 的不默认自动发送规则](../PRD-recording-ai-actions.md)。

## 4. 自带密钥的问题不能用“一次”化解

对这批普通用户，注册第三方账号、理解密钥、申请权限/额度、复制设置属于明显的使用门槛；“只填一次”减少重复劳动，却没有解决首次价值尚未感受到、后续密钥失效或额度不足的问题。当前反馈不支持把自带密钥路线称作普遍容易接受。

| 路线 | 产品体验与决定 |
|---|---|
| 保留单机/自带模型服务 | 面向愿意自行配置、重视控制的用户；首次云整理引导现有设置，保留可体验的虚构示例、清楚费用和发送范围；必须允许跳过。低摩擦文案不能替代实际配置成功率 |
| 提供开箱即用 AI 整理 | 更接近普通用户期待，但需要服务、收费、隐私与运营方案；当前没有这项承诺，不能在原型伪装免配置/免费可用 |

不推荐为新用户默默挑一家服务商、预埋公用密钥或把买断 App 显示成模型永远免费。原型演示用虚构服务状态，不收集或保存真实密钥，也不代替用户去注册账号。合规路线与成本需另行确认，本文不根据聊天讨论作法律结论。

这些是设计评审检查点，不算入历史 35 个正式验收案例，也不将对应 Plane 工作项标完成。

| 编号 | 可检查的行为 |
|---|---|
| UX01 | 已具备必要权限时，一次点击红键进入录音；不先选择标题/地点/整理类型；跨 Tab 仍能回录音或停止 |
| UX02 | 点击详情标题复用编辑入口；保存后详情和列表一致；取消、空标题与保存失败有明确行为 |

| UX04 | 实时文字和说话人未完成状态分别可见；身份不明不猜人名；不展示无依据的精确进度 |

| UX06 | 普通整理清楚显示本条录音、范围、目标服务和实际限制，一次明确操作才开始；能留在本录音查结果，也能进入原聊天调整要求 |
| UX07 | 未配置服务可看示例、跳过并录音/读本地稿；配置返回保留原请求；错误、费用、发送范围可理解，不需要重复跳外部应用 |
| UX08 | 默认阅读与完成提示不含分片、UUID、hash 等诊断字段；缺失范围、来源变更、权限失败等有用信息仍保留 |
| UX09 | 自动地点可关闭，失败不挡录音，可手工纠正；不以原型替代真实权限验证 |
| UX10 | 大字、深浅色、44 pt 目标与 VoiceOver 顺序按 DESIGN 保留；播放器既有底部布局的朗读顺序仍需实际核验 |

## 6. 工程测量与待决定事项

需实测：首次安装/可发现性；首字延迟、持续转写落后时长、停止后全文就绪耗时；相同样本的文字错误与声纹分离/错归情况；seek 定位误差、手动阅读体验；首次 AI 配置完成率、耗时/退出步骤、整理成功与找回结果；各端资料读取、编辑、冲突与删除行为。先建立测量方法和基线，再定目标，不照搬 90%/95% 或竞品的用户印象。

待产品/契约决定：普通整理是否采用上述直接发起路径；对白的润色边界/结果类型；开录默认模式；是否提供免配置 AI 及其服务/收费；哪些资料要跨端及外部知识库目标。原型可以先演示这些提案，但生产实现和 C00 冻结仍遵循既有评审顺序。

依据由根代理与交互智能体只读核对：原型 [app.js](recording-ai-actions-prototype/app.js) 的占位行为；当前工作树和产品主目录的 Home captureDock、RecordingDetailView 标题/metadata Sheet、Slider 与 scrollToActiveSegment、RecordingCoreModel.start、LocationAccess、VoiceContextRootView 模型检查/设置入口。没有复制主目录未提交 UI，也没有运行 iOS、模拟器、模型、定位或 EventKit。
