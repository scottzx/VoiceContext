## 1. 供一次确认的默认提案

| 决策 | 推荐默认方案 | 原因 / 影响 |
| --- | --- | --- |
| P0-01 整理入口 | 沿用录音详情右上「更多操作 → 交给智能体」，在切入聊天前补范围 / 模板 Sheet；「智能体产物」沿用原文件列表 Sheet。保留四内容 Tab 与固定底部播放器 | 复用现有层级，不再增加永久「整理与结果」区 |
| P0-02 输入与发送 | 默认本条录音的整份当前文稿；Sheet 可选择时间范围。现有聊天草稿输入区预填请求，新增固定版本 / 范围摘要；现有发送按钮执行一次，不再追加同义确认或独立发送页 | 保留会话、模型与工具；不会因文稿变更混读版本 |
| P0-03 缺口与临时整理 | 处理未结束或个人录音标「临时整理」；处理已结束但存在缺口标「含缺失的纪要」；旧文稿完整性未记录标「完整性未确认的整理」；已完成、完整、会议录音才标正式「会议纪要」 | 分类绑定固定输入保存；局部范围不宣称覆盖整份，旧 unknown 不升为正式 |
| P0-04 重转写 | 先预检，再生成候选，旧稿保留。默认「保留校对，采纳其他识别段」；整份替换是独立破坏动作，并保留可恢复旧版本 | 默认保护人工劳动；不可稳定映射的段落需逐段核对，不能假称自动保护 |

| P0-07 部分失败与待核实 | 成功项显示保存后回执；只重试明确失败项。「待核实」先查询来源标记 / 映射，不提供盲目重新创建按钮 | 保存成功但回执中断不会产生重复；权限失效不等于被删 |
| P0-08 删除生成物 | 删除录音时默认一起删除派生结果；用户可明确选择保留摘要 / 导图，保留后标「来源已删除」。任何选择都清理受管原文、快照、旧校对稿与候选 | 隐私默认明确；保留摘要不等于保留完整原文；此默认仍需 Human 确认 |
| P0-09 音频保留 | 维持默认 7 天，正在处理也不自动延期；将过期时显示风险和「长期保留」明确操作 | 不擅自改既有保留政策；此默认仍需 Human 确认 |
| P0-10 输入范围说明 | 每次草稿保留可读的发送摘要；不增加永久「不再提示」开关。默认仅所选文字、来源元数据和模板，不附原始音频 | 不扩大到其他录音 / 附件；具体操作已授权时不另加重复弹窗 |
| P1-01 导图首版 | 单列可折叠树 + 文字等价视图；节点来源可回跳；Markdown 与 Mermaid 图描述导出 | 不要求自由画布 / 缩放；格式需评审后纳入 C00，P1 不阻塞 P0 |

接受上述默认提案即可作为对应 D 任务的评审结论输入；**本文的存在不是接受记录**。实现前 C00 还需明确候选段落映射失败、来源链接载体、列表能力、删除 tombstone、导图层级 / 节点上限等技术规则。尚未确定的字段名和目录格式不进入产品文案。

与 C00 对齐的私有保存边界：确认意图、请求权威元数据、关联映射与删除进度默认仅在应用私有本机目录保存，本轮不默认同步 iCloud；不保存凭据、额外全文或另一份事项完成状态。模型只获得用户所选工作副本与模板 / 必要来源元数据，共享副本不是不可写权威。确认页可以说明「关联与处理记录保存在本机」，不暴露日志路径或格式。

## 2. 信息层级与视觉约束

沿用四 Tab 顺序：聊天、会议、待办事项、拓展。录音详情沿用标题 / 元信息 → 四内容 Tab（逐字稿、参会人与声纹、详细信息、备忘录）→ 当前内容，底部固定播放 / 录音控制可达。新增完整性放在逐字稿既有进度区，音频保留放在详细信息，操作沿用更多菜单；不重排既有详情。播放器在源码中是底部 `safeAreaInset`，与 DESIGN 中“音频先于文稿”的阅读顺序要求存在待核对差异，本轮先保留真实结构，生产落地需确认 VoiceOver 朗读顺序，不暗称已通过。原文引用优先回到详情逐字稿定位同版本段；旧版引用需要最小只读快照子页，不能静默改到新版相似句。

系统字体；主目录已采用 `YimaDesign.Typography` 与布局 token，新增部分继续用相同角色，正文 / 条目默认 17 pt、元信息 15 pt，状态和紧凑时间按既有角色；不固定最终行高。页边距 20 pt / 列表 16 pt，章节间距 24 pt，内容行至少 64 pt、表单操作至少 44 pt，独立主要按钮 52 pt。大字号时元信息和按钮换行，行高自然增长。

全部普通条目为平面列表与细分隔线，文稿和纪要像文档。只有播放器、原生 Sheet 与实际控制区可用独立表面。黑白灰主导，红仅用于录音与真正删除 / 整份替换；处理中和注意状态使用小标记与文字，系统设置 / 系统链接才使用蓝色。成功反馈可使用小绿标记，普通已完成记录仍保持中性。无渐变、阴影、逐行卡片和桌面分栏。

## 3. D01：预检、完整性与校对保护

沿用「更多操作 → 重新转写 / 分析」，以及文稿里已有的失败重试按钮；所有入口前接同一预检。检查可处理音频范围、不可处理范围及原因、旧文稿 revision、人工校对数量。无可读音频时没有开始按钮，说明「音频已过期，不能重新转写。现有文字和校对仍保留」。部分可读时按钮明确「仅重试可用范围」，不能称整份重转写。

开始只产生候选版本，当前阅读版本不变。候选页单列呈现每段「当前文字」和「新识别候选」，显示校对标记与来源范围；每段都可保留当前 / 采纳候选。默认保留校对段，采纳未校对且能稳定映射的段。无法稳定映射的片段显示「需要核对」，不自动采纳；并发人工编辑时提示版本冲突，重新比较，不把候选强写到当前 revision。

「整份替换」单独确认：「本次将替换包括人工校对在内的全部文字；上一版本仍可恢复」。取消不改稿。候选失败、被取消、迟到回调均不改变已保存旧稿。采纳后才产生新 revision；旧结果标来源更新。

| 实际内容 | 显示文案 | 恢复动作 |
| --- | --- | --- |
| ASR 在处理 | 处理中 · 已有 00:00–08:20 的文字 | 查看进度 / 用现有文字临时整理 |
| 有不可恢复范围 | 部分可用 · 08:20–09:00 音频缺失 | 查看缺口 / 生成含缺失的纪要 |
| 正常静音 | 此范围为正常静音，没有需要转写的语音 | 查看其他范围；没有文字时不能发起整理 |
| 有声但识别为空 | 检测到声音，但没有识别出文字 | 在音频可用时重试 / 手工补充 |
| 识别失败 | 此范围识别失败；旧文字已保留 | 按范围重试 |
| 已校对 | 已校对 · 3 段人工修改 | 阅读 / 比较候选 / 查看旧版本 |
| 老文稿无新字段 | 完整性信息未记录 | 阅读；不自动标完整 |

## 4. D02：整理、运行、结果与历史

「交给智能体」继续走 Root 已有模型检查及草稿切换，仅在切换前插入 Sheet。默认「会议纪要」，可改为「行动建议」，P1 导图入口注明独立范围。选择模板与整份 / 时间范围；显示 revision、完整性、缺口、录音发生时间 / 时区、已配置模型服务。没有模型时复用 Root 已有「尚无可用聊天模型 → 配置模型与服务」；没有可用文字时返回文稿，不能创建空纪要。格式不支持时提供文稿 / 文件降级入口。范围选择不得落在不存在的来源段外。

「准备聊天草稿」固定输入。选择范围按完整 segmentIDs，显示实际覆盖边界；模型工作副本仅含所选文字和明确元数据 / 模板，不携带未选原文。C00 分别记录完整 canonical 文稿摘要与实际选定输入摘要，界面只显示版本与范围。沿用 `ContentView → AIChatView → CachedViewModel.inputText` 预填路径；在既有输入区上方加简短来源摘要 / 展开详情，保持模型与工具原控件。用户可编辑整理指令，现有发送按钮就是一次执行授权；来源选择重新准备，不允许编辑指令悄悄扩大固定输入。若发送前文稿更新，显示「此草稿使用已选版本 12；当前是 13」并提供「改用新版」重新制作草稿，不悄悄换输入。离线仍可读本地数据，模型服务不可用时发送禁用并说明。原型聊天外壳为源码结构示意，未复制完整会话功能。

运行继续显示在原聊天；「智能体产物」Sheet 中补处理记录，打开最小状态子页可返回录音、打开关联聊天、停止。无需新建并列运行首页。取消不删除已经提交的历史结果。中断显示「处理已中断，尚未提交新结果」，可打开聊天 / 恢复核对；不会因目录存在临时文件显示完成。

沿用 `RecordingAgentResults` 的 NavigationStack / 文件 List / 完成按钮 / 刷新 / QuickLook。补已提交索引与文件行的类型、来源版本、覆盖、来源更新等摘要；失败 / 中断记录放处理记录区。结果标题保留「会议纪要 / 临时整理 / 含缺失的纪要」。纪要文件内容区分主题摘要、讨论、已明确决策、行动建议、未解决问题；建议不升格为决定，疑似身份不写成确认负责人。普通文件继续 QuickLook，App 的最小产物信息子页提供来源与行动确认入口；不把独立自研富文本阅读器当本轮既有能力。显示已覆盖与未覆盖范围，关键段落有可点击来源。

「历史结果」列来源版本与生成状态；新版产生时旧结果仍可看并显示「来源已更新」。旧无 manifest 文件列「历史文件 · 来源版本与完成状态未记录」，保留文件预览入口，不伪造 metadata。损坏格式 / 来源校验失败不作为正式产物，必要时「查看原文件」。分享仅导出所显示的派生结果，并说明是否包含引用元数据。

## 5. D04：行动候选、确认与关联

建议区清楚写「尚未创建系统事项」，默认全部未选择。每行有选择框、标题、负责人事实或「待确认」、到期、提醒、目标账户 / 列表与来源。负责人字段只说明原文信息，不表示可把任务分配给他人。未确定日期显示「无日期 / 待确认」，不猜日期。

相对日期展示解释：「原文‘下周’，以录音发生时间 2026-10-02、Asia/Shanghai 为依据；具体日期尚未确认」。无法精确解释时保留无日期；用户可明确填写。相似候选显示已关联事项或「可能重复」及来源差异；「这是另一件事」明确生成新确认意图，同标题不能自动合并。

编辑保存只改候选。选择后进入核对页，逐项展示本次精确标题、账户 / 列表、到期、通知、备注与来源；唯一写入授权是「确认创建 X 项」。取消核对保留候选，零系统写入。保存 intent 后冻结该次 payload，连续点击的同一 intent 使用同 request ID。

| 结果 | 显示与可操作项 |
| --- | --- |
| 已创建 | 实际保存标题、账户 / 列表、due、alarm、系统 ID、request ID；打开待办详情 / 来源 |
| 已创建但设置有差异 | 明确系统实际设置与确认值的差异，提供查看 / 编辑现有事项；它已经创建，不能作为失败再次创建 |
| 创建失败 | 具体原因；保留候选；只重试失败项，成功项不能再被勾选 |
| 待核实 | 保存结果尚未确认；核实结果 / 供人工核对的准确来源标记；不出现重新创建 |
| 权限撤销 | 暂不可读取系统事项；去系统设置 / 刷新；不能推断它已被删除 |
| 外部完成 / 修改 / 移动 | 刷新系统实际状态和内容；引用仍指向原来源 |
| 外部删除 | 系统事项已删除，来源仍在；「明确另建」形成新操作，不自动补建 |
| 来源删除 | 系统事项保留，显示来源已删除；不再提供失效原文回跳 |

「在待办事项查看」切入原 `SystemRemindersView`，定位系统对象并打开已有 `ReminderEditor`；在原表单尾部补只读来源关联区。日期总览、全部列表、完成 / 恢复、编辑 / 删除继续使用现有功能，不新建第二个待办详情或首页。纪要关联区提供反向入口；系统 Reminder 中 URL / 备注载体由 C00 技术评审决定，网页仅演示 App 内回跳。

## 6. D05：账户、列表、due 与 alarm

选择器列账户后列列表，例如「iCloud · 工作」与「公司 · 工作」。只读行显示「只读，不能创建」，失效列表显示失效；用户已经选定的 ID 不静默回退。明确目标不可写时核对按钮不可执行，保留候选供换列表。名字多义需用户选具体条目，默认不能取第一项。

编辑页的「到期」和「定时提醒」是两个独立字段：无 / 仅日期 / 日期和时间；通知无 / 日期时间。到期带时间和通知必须显示时区。只设到期显示「未设置定时提醒」；独立通知无需给事项补一个到期。回执读保存后的系统对象，若能力不支持用户要求就失败，不能偷偷去掉通知后称成功。

核对页与回执均把到期放左、提醒放右；大字号时换行并保留标签。重复、位置、相对通知、多 alarm 等复杂组合沿用既有保护；编辑页显示「此时间组合需在系统提醒事项中处理」，不破坏已有设置。无效日期显示字段错误并禁止写入；保存失败与结果不明分别呈现。

关键文案：「已设置定时提醒」只描述保存后的 alarm，不描述通知已到达。真实通知与权限、录音连续性属于 T06/T07 授权真机验证范围。

## 7. D06：保留、删除与发送范围

音频保留页显示到期日、默认 7 天、将到期任务风险，以及用户明确的「长期保留」。音频到期后，播放器位置显示音频不可用，仍保留文稿、结果和事项；不通过恢复任务自动延期。

删除录音确认分成平面范围行：

| 对象 | 默认处理 |
| --- | --- |
| 音频、canonical 文稿、公开 Meetings / Daily / Source 副本 | 删除 |
| AI 固定输入快照、旧校对版本、重转写候选 | 始终删除，不能因保留摘要而留原文 |
| 进行中的来源运行 | 取消并撤销继续读取 / 提交；迟到结果不得复活来源 |
| 摘要、纪要、导图和未确认行动建议 | 默认删除；可明确保留摘要 / 导图，未确认建议失去创建能力 |
| 已创建系统提醒事项 | 保留；关联标来源已删除，不自动删系统事项 |
| 用户自行导出文件、已发送第三方模型内容 | 不承诺撤回；说明 App 受管清理的边界 |

删除页有明确取消，真正删除按钮用红色。单删和批删都报告逐对象结果；「文稿副本清理失败」不是全部删除成功。未完成清理入口为「继续清理」，既有撤销状态持续阻止 Source 再发布；不提供把残留作为新来源打开的按钮。系统事项删除另有既有确认，不反向删除录音。

模型发送摘要：本条录音选定版本文字、所选范围、必要时间 / 说话人 / 完整性元数据、用户选择的模板；显示实际配置模型服务。默认不含其他录音、附件、原始音频、凭据、数据库、journal 或声纹数据。通用 Agent 的广泛文件能力不扩大本次整理授权。跨录音 / 附件 / 音频必须是另一次明确操作。

## 8. 全状态与无障碍

| 条件 | 入口 / 文案 / 动作 |
| --- | --- |
| 正常 | 阅读本地文稿，创建草稿，查看结果 |
| 空文字 | 还没有可整理的文字；查看转写，不执行空请求 |
| 加载 | 正在读取文稿 / 正在核对系统事项；本地已有内容继续可读 |
| 处理中 | 显示真实已知阶段，不制造百分比；临时整理可按已读范围发起 |
| 无模型 | 未配置可用模型；进入现有模型设置 |
| 离线 | 本地文字可读；模型服务当前不可用，保留草稿 |
| 失败 / 取消 / 中断 | 旧稿和已提交结果保留，分别标识原因与恢复动作 |
| 权限受限 / 只读 | 保留候选，显示授权或换列表，不返回空列表冒充无事项 |
| 音频过期 | 保留播放器位置解释，来源仍定位文字 |
| 来源已更新 | 明示绑定版本与当前版本，不改旧结果 / 系统事项 |
| 来源已删除 | 保留结果如有明确选择，原文回跳禁用并说明 |
| 部分删除失败 | 显示未完成对象和继续清理，不宣称已全部删除 |

朗读顺序：详情标题 → 元信息 → 播放器 → 文稿状态 / 缺口 → 文稿段落 → 整理 / 结果 → 次级操作。来源页先读版本、时间范围与音频可用性，再读所定位文字。候选页先读「未创建」说明，每行读选择状态、标题、缺失信息、到期、提醒、列表与来源，最后核对按钮。回执逐项宣读真实状态；待核实不会读成失败。

Sheet 移动焦点到标题，取消 / 返回恢复到发起按钮；主要按钮与图标均 ≥44 pt。状态变化采用 polite 公告，不逐秒朗读时间。树节点告知展开 / 收起与层级；文字等价视图全部可读。颜色之外都有文字标签。中英文、深浅色、accessibility3、Reduce Motion、长标题和时区文字均列入实现验收；网页大字模拟只能发现排版问题，未代替这些验收。

## 9. P1 D03：导图独立附录

首版是原生折叠树，根节点为录音主题，子分支可按讨论、已明确决策、行动建议、未解决问题组织。类型是整理分类，不暗示因果。节点标题和说明允许增长；来源为独立 44 pt 动作，行动节点进入现有候选确认。大字体可切文字等价视图，保留层级和来源。

Markdown 导出保留嵌套标题 / 列表与引用元数据；推荐 Mermaid 作为第二种图描述格式，附 recording / revision 与节点来源对应表，避免只导出一张无来源图。文件名和实际格式由 C00 后续补冻结。导出仅包含当前导图及其引用元数据，不自动带原始音频 / 全文。浏览器示例下载不调用模型或系统分享。

循环、非法父引用、来源损坏、超深层级、未完成提交各显示「导图结构无法读取」，可以查看可验证文字降级文件；不得把未校验任意 JSON 当完整导图。失败不影响纪要与原文。具体深度 / 节点上限是技术待决策，评审无需承诺自由画布。

## 10. 原型走查与交付状态

1. 现有会议列表 → 录音详情（四内容 Tab 与底部播放器）→ 更多操作 → 交给智能体 → 范围 / 模板 Sheet → 现有聊天草稿 → 原发送按钮 → 用评审控件模拟完成 → 智能体产物 Sheet → 文件预览 / 来源信息。
2. 评审状态切「部分可用」与「处理中」：标题分别为含缺失 / 临时，范围说明保留；「来源更新」保留原草稿版本。
3. 行动建议勾选三项 → 编辑账户 / 列表、独立到期 / 通知 → 核对 → 确认 → 查看成功 / 失败 / 待核实 → 只重试失败、核实不再写。
4. 音频过期 → 重转写不可开始，旧稿可读；可用音频 → 新候选 → 默认保留校对 / 整份替换独立确认。
5. 沿用会议列表行的删除菜单 / 侧滑 / 批量删除入口 → 在原确认处扩展全部受管范围与系统事项保留 → 可选择保留摘要 / 导图 → 清理成功或部分失败 → 不再打开原文。详情更多菜单不凭空增加删除入口。
6. P1 导图 → 展开 / 收起、文字阅读、来源、行动建议、Markdown / Mermaid 示例导出。
