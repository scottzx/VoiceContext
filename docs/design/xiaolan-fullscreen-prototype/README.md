# 小蓝语音模式：拓展入口与 App 内导航原型

设计依据：[修订设计](../xiaolan-fullscreen.md)与[DESIGN.md](../../../DESIGN.md)。日期：2026-10-17。

用户已确认从底部「拓展」开启语音模式，与未结束录音互斥；取消独立小蓝前端，页面直接在 App 内跳转。本次重做原型中的入口与导航，替代先前的独立全屏页面；路径保持不变，已有预览地址仍有效。

入口：[index.html](./index.html)，可直接打开；本机服务运行时可使用[交互预览](http://127.0.0.1:4191/xiaolan-fullscreen-prototype/)。HTML/CSS/JavaScript 均为本地文件，无构建与第三方依赖。电脑右侧是评审控制，不属于 App；窄屏评审控制在 App 画布下方。

## 点击路径

1. 默认显示「拓展」。在工具组点「语音模式」：仍留在拓展，入口显示已开启，页头出现原生麦克风控制。
2. 用评审控制模拟“打开今天的日程”：切到提醒根页，四个底部 Tab 保留。模拟“打开待办”：进入待办详情，按现有约束隐藏 Tab；返回后仍是提醒页。
3. 在开启状态下点页头麦克风，打开原生菜单；可点击说话（输入模拟）、暂停、继续或关闭语音模式。关闭只结束语音，不离开当前页。
4. 模拟“文字/图片/图表/HTML”：打开普通 App 内容预览，返回原聊天会话。图片可以放大，图表可切换柱/折线并查看数据表，HTML 可展开页面内内容。
5. 在评审控制点“已有录音”，再点拓展中的“语音模式”：提示“请先关闭录音”，取消后录音仍在，语音仍关闭。
6. 选择“前往当前录音”：只打开原录音详情。暂停不会解除互斥；必须明确点“结束录音”并保存，之后回拓展主动开启语音。
7. 用“录音暂停未结束”重复检查阻止流程，不能把暂停当作结束。
8. 恢复正常 → 开启语音 → 底部会议 → 开始录音：提示先关闭语音模式。通过原生菜单关闭后仍不会自动录音，需再次点开始。
9. 检查后台暂停、权限说明、旧任务不抢页、深浅色、大字号与窄屏。

## 边界

- App 页面为既有页面职责的简化演示，不要求重写聊天、会议、提醒、拓展或各预览。四 Tab 按 `DESIGN.md` 显示；实际融合代码当前第二 Tab 的“记录”标签与规范“会议”的差异不属于本轮实施范围。
- 模拟指令必须先开启语音；页面本身也可通过触摸进入。没有独立小蓝首页、独立导航外壳或常驻底部语音条。
- 日期固定为 2026-10-17，业务数据、录音时长和内容都是虚构示例。录音/语音状态仅存在浏览器内存，不调用真实麦克风、模型、录音、TTS、系统资料或保存操作。
- 录音示例中的“结束并保存”只改变演示状态；正式实现仍须等待原有安全保存完成，不能用同步原型行为代表录音生命周期验收。
- 图表是本地 SVG，图片为白板 SVG；放大仅演示完整查看，正式捏合缩放须复用原有图片预览。图表 renderer 的 App 接入尚未实现。
- HTML 用 sandbox iframe 和无脚本 details 交互，不等于 WKWebView 的原生权限、资源与媒体隔离已经验收。
- 浏览器刷新重置状态；原生会话持久化、后台恢复、竞态和全入口互斥需要工程实现后验证。

## 验证记录

2026-10-17，使用 `browser-skill` 在独立桌面浏览器会话重新检查当前修订：

- 拓展入口可开启语音，开启后仍在拓展；根页显示四个 Tab，待办等详情隐藏 Tab，原生返回恢复根页。页面切换时同一语音状态保持开启，没有底部语音条。
- 已有录音时出现「请先关闭录音」；取消不结束录音。前往录音详情后录音仍存在，暂停后返回拓展依然阻止语音开启。
- 暂停录音的检查中，实际演示状态为 `recording=paused`、`voice=off`；明确结束并保存后为两者关闭，没有自动开启语音。
- 语音开启时点开始录音出现反向提示；通过菜单关闭语音后，两者仍关闭，需再次点开始才进入录音。
- 文字预览返回既有聊天会话；图片放大与 Escape 关闭、折线图切换及数据表、HTML 键盘展开均可操作。图表 DOM 显示折线选中，语音状态仍开启。
- 后台演示变为暂停，需主动继续；权限失败不启用；停播、旧任务不抢页和关闭后的迟到结果处理通过。
- 393×852 及深色大字号 320×740 CSS 视口无页面/内容横向溢出，检查到的产品按钮至少 44×44。已目视检查拓展入口、录音冲突、图表和深色窄屏。
- JavaScript 语法、文档引用、SVG 和差异空白检查通过。未观察到原型脚本异常；扩展自身 `chrome-extension://invalid/` 错误单独记录。
