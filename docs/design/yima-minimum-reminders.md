# 最小迭代：待办交互与数据规则

2026-10-01，依据用户启动 `docs/discussion/yima-minimum-iteration.md` 的开发指令。沿用 `DESIGN.md` 已确认风格；本文件记录实施选择，视觉和运行验收仍待真机证据。

- 平铺原生 List，紧凑标题；工具栏为筛选 Menu 和唯一新增按钮。默认全部未完成；可选择系统列表及显示已完成。筛选到可写列表时新增使用该列表，否则使用系统默认可写列表。
- 圆圈、滑动及长按菜单均可完成/恢复；行正文打开编辑 Sheet。成功后短暂显示已完成状态再隐藏，提供系统成功触感。处理中禁用同一事项操作，失败不显示成功。Reduce Motion 下不做位置动画。
- 删除通过原生确认对话框，禁止全滑删除；正文、菜单和 VoiceOver 自定义操作为手势替代入口。只读事项可打开详情但不能保存、完成、删除或复制到另一列表。
- 编辑使用 Form：标题、备注、列表、到期日期、可选时间、独立的定时提醒日期时间。到期日期不隐含通知。通知到达取决于系统设置，必须另做真机验收。
- 日期/提醒开关初始值来自系统；仅修改用户变更的字段。日期编辑沿用原时区和日历，仅改日期时保留时分秒；新增带到期日期时补起始日期。重复、相对提醒、位置、多提醒组合在本编辑器只读时间设置，提示用系统提醒事项处理，其他字段仍可编辑。
- 保存和行操作先重新取得系统对象并检查权限、删除和只读状态；失败 reset 未保存对象。读取失败单独呈现并可重试，不能用空列表代替；未申请、拒绝、受限、读取中、无事项、无可写列表有不同说明。外部变更和前台恢复触发查询。
- 文稿缺失时录音详情展示真实状态；未配置模型时给出现有模型配置 Sheet；草稿先整理建议，用户明确确认后创建，不猜日期，结果不明先查询，回报系统 ID/列表/到期日期。产物仍写 `Generated/<recordingID>/`。

工具契约：`RemindersOffload.m` 委托 `CalendarOffload.m`；`--due` 当前只写日期组件，不创建定时 EKAlarm。本轮不扩展 CLI。UI 使用独立绝对日期 alarm。参考 [Apple 创建事件和提醒事项](https://developer.apple.com/documentation/eventkit/creating-events-and-reminders)、[到期日期组件](https://developer.apple.com/documentation/eventkit/ekreminder/duedatecomponents)。

验证：设备 SDK 编译与融合装配审计；macOS 上纯日期规则回归检查，不访问提醒事项、不启动 iOS。真机流程使用专用演示列表，须另获明确运行授权；不使用模拟器。
