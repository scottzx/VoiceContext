## 目标与场景

打开待办 Tab 即可知道哪天有安排，并处理今天的待办；查看其他日期时，同屏看到当天待办和日程。“全部”承接长期维护，不把完整管理功能挤进首页。

原型阶段交付为设计文档和可点击网页原型，示例数据不代表系统记录；原型不读取用户日历、提醒事项。2026-10-02 开发将此流程接入 App 的 EventKit 数据，按系统日历列表与系统提醒事项列表组织来源；日程为只读展示，待办沿用系统提醒事项。没有新增独立任务数据库、AI 自动排期或通知承诺。

实现补充：全部页先读取今天起未来一年的日程，标明已读取范围，并提供“加载更多日程”按年延长；提醒事项没有此范围限制。来源多选以各自系统标识保存，已有待办列表单选迁入管理页偏好；首页始终显示全部可读来源。跨日事件按本地日交集展示，全天结束边界不多算一天。界面编译完成不等于真机视觉、手势或权限验收。

## 信息架构与流程

首页只有两个主组件：

1. **日历**：独立月历控制面板，星期一开始。月标题左对齐，右上角为无底色、无边框的“今天”文字入口，命中区至少44pt；不显示前后切换按钮。左滑查看下一月，右滑查看上一月；周历模式左滑下一周、右滑上一周，手势仅响应日历日期区域的明确横向滑动，纵向仍滚动页面，滑动后不误选日期。点击“今天”恢复今日日期及所在月／周，保留月历／周历展开状态。月历切换仅浏览月份，下方保留所选日事项，点击日期后再更新；周历切换将所选日移动一周。点击月份旁的箭头可收起为选中日期所在的一周。今天与选中日期分开表现：今天数字加细圈，选中日期采用黑底白字／白底黑字。日期下红点表示有未完成的到期待办，绿点表示有日程；同日两类都有则并排显示红、绿两点。图例明确“待办／日程”，不代表逾期、通知或事项数量。
2. **今日事项**：标题右侧为“全部 ›”和唯一“＋”新增待办入口。组件内部先“待办”，后“日程”，各自使用平铺行和细分隔线；不再添加“全部任务”重复入口卡片。非今天日期将标题改为“10月2日 · 周五事项”，回到当天统一使用日历右上角“今天”，事项区不重复放入口。

主路径：待办 Tab → 选中日期 → 勾选待办／点击正文编辑／点击日程看详情。

管理路径：今日事项“全部” → 全部事项管理页 → 原生返回 → 原日期、月份和展开状态恢复。

“全部”不放日历组件，也不提供“时间／日历”切换或类型下拉；直接展示筛选后的事项列表。不继承首页选中日期限制，按“逾期／今天／未来／未安排”分组，组内按日期及时间排序。右上角筛选分为“日历列表”和“待办列表”两组，每个系统原生列表各一个勾选项，可跨两组多选，勾选即更新显示内容。初次进入默认勾选全部可读列表；用户选择在当前原型会话中保留，返回首页不影响首页内容。正式版偏好保存按系统列表标识符区分日历与提醒事项，不能按可能重名的标题匹配，不新建App分类。取消某个来源只隐藏其事项，不修改系统列表或删除数据。

保留“显示已完成待办”作为附加筛选；日程没有完成状态。两组均未勾选时，明确提示“尚未选择列表”，不能误报没有事项；系统来源不可读则说明权限／错误状态，不能冒充列表为空。列表被删除或权限改变后，剔除失效标识符并说明，不自动重新勾选用户已取消的来源。日历与待办来源互不影响，可只选日历、只选待办，也可混合选择。

首页“＋”复用已有 ReminderEditor，新增建议预填所选日期；用户在表单里确认或关闭日期，时间与通知仍独立设置。

**原型前现状**：此前页面是系统提醒事项平铺 List，具备列表筛选、显示已完成、新增、编辑、完成、恢复、删除和权限状态；本轮新增时间分组、首页日期导航、来源列表多选和系统日历日程。“全部”复用既有行与编辑交互。

## UI/UX 风格确认

- 状态：已确认的既有规范复用；新流程细节为本次提案。
- 适用规范：`DESIGN.md` 2026-08-03 已批准规范，含 2026-09-29 四 Tab 与统一平铺列表约定；章节为 Typography、Color、Spacing、Layout、Accessibility。
- 用户本次明确选定参考图的双组件方向，随后明确红点代表待办、绿点代表日程与原生列表筛选；2026-10-02明确全部页移除日历，直接多选日历／待办来源列表；记录为局部语义例外，见项目决策日志。
- 一句话感受：打开就知道今天要做什么、什么时候有安排。
- 关键词：安静、原生、黑白、清晰、适度紧凑。反向关键词：彩色卡片墙、装饰渐变、浮夸阴影、过大留白。
- 以平台原生感为主，品牌沿用既有字体和四 Tab，不新增品牌视觉。
- 字体为系统语义字体；页标题 inline；日历可使用一个 16pt 圆角中性控制面板；日期选择为中性反差；红／绿点 4pt，仅用于日期类型标记，不增加彩色导航或事项行。待办／日程保持平面列表。
- 深色黑色画布与中性面板，浅色白色画布与 grouped 面板；无彩色光晕。月历与今日组件间距 24pt，页面左右 20pt。
- 参考图借鉴月历、今日入口与层级，避免复制大圆角任务卡和第三个重复的“全部任务”组件。
- 操作命中区至少 44pt；大字体时月历可收起成周、提供日期选择替代入口，内容行自然增高；VoiceOver 日期描述包含完整日期、今天、选中、待办与日程数量／读取状态，不能仅靠红绿颜色；原型支持日历焦点上的左右方向键翻页，正式iOS提供VoiceOver上一月／下一月或上一周／下一周自定义操作，屏幕不增加翻页按钮；Reduce Motion 不做位移动画。
- 原型是网页视觉与流程评审工具，不能验证真实 iOS Dynamic Type、VoiceOver、触感或系统字体度量。

## 行规则与数据边界

- 待办：圆圈完成操作；正文编辑；标题优先，时间／全天／来源列表次之。完成成功后短暂显示勾选与“已完成”再隐藏，失败保留并说明。只读列表保留详情入口，禁用写入。沿用现有保存、删除确认及复杂时间设置保护。
- 日程：起止时间或“全天”在左，标题与来源在右；使用日历语义而非完成圆圈。跨午夜事件出现在所有相交日期，全天结束日期按系统的结束边界处理。网页原型日程详情仅展示示例，正式编辑入口待日历范围确认。
- 今日未安排时间的待办位于有时间待办之后；没有到期日期的待办不猜日期，不在某天打点，仍可从“全部”的“未安排”找到。逾期待办从“全部”的“逾期”查找；首页可在待办摘要中提示逾期数量，不能伪装为今日到期。
- 日历红色待办点与绿色日程点分别依据该来源成功读取的数据计算。某来源未授权／读取失败时，显示来源状态，不声称“没有安排”。已完成待办不计点；日程不因结束就消失，仍可回看。
- 系统提醒事项仍是唯一待办事实源；页面和 Agent 共用同一数据。日程以系统日历为源，权限单独管理。只有可重建查询结果与 UI 偏好，不保存平行的完成状态。
- 使用当前系统日历／时区的本地日边界筛选，保留来源时间字段。前台恢复与 EventKit 外部变更刷新首页、红绿点和管理页。

## 状态、权限与隐私

| 状态 | 页面表现与恢复 |
|---|---|
| 正常 | 两类事项独立显示数量，日期选择同步两类内容 |
| 当天无事项 | 待办“这天没有待办”，日程“这天没有日程”；保留全部与新增 |
| 首次未授权 | 各来源独立说明用途，用户点“允许访问”才请求对应权限 |
| 拒绝／受限 | 只在受影响子区说明，提供系统设置入口；另一来源继续可用 |
| 读取中／失败 | 分来源加载／错误与重试，不转换为空列表或清除已知安排而不解释 |
| 无可写列表 | 禁用新增并解释，保留可读内容；不改变系统默认列表 |
| 更新失败／外部删除 | 保留真实状态，提示后刷新；不假成功或重复写入 |
| 离线 | 依赖 EventKit 本地可见数据，不把系统同步状态宣称为最新云端状态 |
| 录音进行中 | 沿用全局录音条，首页内容让位，停止入口仍可达 |

不在打开待办 Tab 时同时弹两项权限。日历接入的实际权限配置、说明文案与只读展示范围需工程核查。日程及待办不因原型／UI 改版上传；不自动把日程送到 Agent 或写入会议记录。
