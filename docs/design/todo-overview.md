## 目标与场景

打开待办 Tab 即可知道哪天有安排，并处理今天的待办；查看其他日期时，同屏看到当天待办和日程。“全部”承接长期维护，不把完整管理功能挤进首页。

原型阶段交付为设计文档和可点击网页原型，示例数据不代表系统记录；原型不读取用户日历、提醒事项。2026-10-02 开发将此流程接入 App 的 EventKit 数据，按系统日历列表与系统提醒事项列表组织来源；日程为只读展示，待办沿用系统提醒事项。没有新增独立任务数据库、AI 自动排期或通知承诺。

实现补充：全部页先读取今天起未来一年的日程，标明已读取范围，并提供“加载更多日程”按年延长；提醒事项没有此范围限制。来源多选以各自系统标识保存，已有待办列表单选迁入管理页偏好；首页与全部页共用已保存的来源与完成状态筛选。跨日事件按本地日交集展示，全天结束边界不多算一天。界面编译完成不等于真机视觉、手势或权限验收。

## 信息架构与流程

首页只有两个主组件：

1. **日历**：独立月历控制面板，星期一开始。月标题左对齐，右上角为无底色、无边框的“今天”文字入口，命中区至少44pt；不显示前后切换按钮。左滑查看下一月，右滑查看上一月；周历模式左滑下一周、右滑上一周，手势仅响应日历日期区域的明确横向滑动，纵向仍滚动页面，滑动后不误选日期。点击“今天”恢复今日日期及所在月／周，保留月历／周历展开状态。月历切换仅浏览月份，下方保留所选日事项，点击日期后再更新；周历切换将所选日移动一周。点击月份旁的箭头可收起为选中日期所在的一周。今天与选中日期分开表现：今天数字加细圈，选中日期采用黑底白字／白底黑字。日期下红点表示有未完成的到期待办，绿点表示有日程；同日两类都有则并排显示红、绿两点。2026-10-02 用户补充：移除底部常驻图例，在“今天”右侧添加 44pt info 按钮，点击显示原生浮层说明“红色：待办／绿色：日程”；颜色说明不代表逾期、通知或事项数量。空间不足时标题栏换行，今天与 info 保持相邻。
2. **今日事项**：标题右侧为“全部 ›”和唯一“＋”新增待办入口。组件内部先“待办”，后“日程”，各自使用平铺行和细分隔线；不再添加“全部任务”重复入口卡片。非今天日期将标题改为“10月2日 · 周五事项”，回到当天统一使用日历右上角“今天”，事项区不重复放入口。

主路径：提醒 Tab → 选中日期 → 勾选待办／点击正文编辑／点击日程看详情。

管理路径：今日事项“全部” → 全部事项管理页 → 原生返回 → 原日期、月份和展开状态恢复。

“全部”不放日历组件，也不提供“时间／日历”切换或类型下拉；直接展示筛选后的事项列表。不继承首页选中日期限制，按有事项的日期分组，无日期待办放在“未安排”。日期标题可打开原生年月日滚轮跳转，空日期不生成选项。首页与全部页共用原生筛选 Sheet，顶部可切换日历／待办来源类型；筛选分为“日历列表”和“待办列表”两组，两组分别打开 EKCalendarChooser 原生多选，点击完成保存并更新首页与全部页，取消或划掉选择器不修改保存的选择。初次读取默认勾选全部可读列表；首页右上角也提供筛选入口，两页共用同一份全局持久偏好。来源、显示已完成选项和全部取消均自动保存，返回、切换 Tab 或重开 App 后保留。偏好按系统列表标识符区分日历与提醒事项，不能按可能重名的标题匹配，不新建App分类。取消某个来源只隐藏其事项，不修改系统列表或删除数据。

保留“显示已完成待办”作为附加筛选；日程没有完成状态。两组均未勾选时，明确提示“尚未选择列表”，不能误报没有事项；系统来源不可读则说明权限／错误状态，不能冒充列表为空。列表被删除或权限改变后，剔除失效标识符并说明，不自动重新勾选用户已取消的来源。日历与待办来源互不影响，可只选日历、只选待办，也可混合选择。

首页“＋”复用已有 ReminderEditor，新增建议预填所选日期；用户在表单里确认或关闭日期，时间与通知仍独立设置。

**原型前现状**：此前页面是系统提醒事项平铺 List，具备列表筛选、显示已完成、新增、编辑、完成、恢复、删除和权限状态；本轮新增时间分组、首页日期导航、来源列表多选和系统日历日程。“全部”复用既有行与编辑交互。

## 行规则与数据边界

- 待办：圆圈完成操作；正文编辑；标题优先，时间／全天／来源列表次之。完成成功后短暂显示勾选与“已完成”再隐藏，失败保留并说明。只读列表保留详情入口，禁用写入。沿用现有保存、删除确认及复杂时间设置保护。
- 待办日期展示（2026-10-04）：首页与全部页卡片只展示到期日期／已设置的到期时间，不展示通知提醒日期及铃铛行；没有到期日期则不显示日期，也不以提醒时间代替。实际通知和编辑页的定时提醒设置保留。
- 日程：沿用待办的标题与来源排版，次级日期行左侧显示日期，右侧显示起止时间或“全天”；地点直接展示名称，不配图标。使用日历语义而非完成圆圈。首页跨午夜事件出现在所有相交日期，全天结束日期按系统的结束边界处理。日程详情通过 EKEventViewController 展示，允许由系统提供编辑；只读／订阅日历及重复日程的编辑范围按系统规则处理。来源与具体开始时间共同定位所选那次日程，关闭详情后刷新两页与日期标记。
- 今日未安排时间的待办位于有时间待办之后；没有到期日期的待办不猜日期，不在某天打点，仍可从“全部”的“未安排”找到。逾期待办从“全部”对应的历史日期分组查找；首页可在待办摘要中提示逾期数量，不能伪装为今日到期。
- 日历红色待办点与绿色日程点分别依据成功读取且已勾选来源的数据计算；首页数量、逾期摘要同样应用全局筛选。某来源未授权／读取失败时，显示来源状态，不声称“没有安排”。已完成待办不计红点，即使选择显示已完成；日程不因结束就消失，仍可回看。
- 系统提醒事项仍是唯一待办事实源；页面和 Agent 共用同一数据。日程以系统日历为源，权限单独管理。只有可重建查询结果与 UI 偏好，不保存平行的完成状态。
- 使用当前系统日历／时区的本地日边界筛选，保留来源时间字段。前台恢复与 EventKit 外部变更刷新首页、红绿点和管理页。

## 状态、权限与隐私

| 状态 | 页面表现与恢复 |
|---|---|
| 正常 | 两类事项独立显示数量，日期选择同步两类内容 |
| 当天无事项 | 待办“这天没有待办”，日程“这天没有日程”；保留全部与新增 |
| 首次未授权 | 各来源独立说明用途，用户点“允许访问”才请求对应权限 |
| 拒绝／受限 | 只在受影响子区说明，提供系统设置入口；另一来源继续可用 |
| 读取中／失败 | 分来源加载／错误与重试，不转换为空列表或清除已知安排而不解释 |
| 无可写列表 | 禁用新增并解释，保留可读内容；不改变系统默认列表 |
| 更新失败／外部删除 | 保留真实状态，提示后刷新；不假成功或重复写入 |
| 离线 | 依赖 EventKit 本地可见数据，不把系统同步状态宣称为最新云端状态 |
| 录音进行中 | 沿用全局录音条，首页内容让位，停止入口仍可达 |

不在打开待办 Tab 时同时弹两项权限。日历接入的实际权限配置、查看／编辑说明与系统编辑限制需工程核查。日程及待办不因原型／UI 改版上传；不自动把日程送到 Agent 或写入会议记录。
