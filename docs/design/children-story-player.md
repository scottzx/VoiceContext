## 2. 目标与边界

家长把已有音频导入 iPhone，打开「拓展 → 儿童故事机」即可播放。小蓝同学通过同一个本地故事库和播放器执行「播放某个故事」「暂停」「继续」「换一个故事」「现在播到哪里了」，并根据真实结果简短回答。页面操作和语音操作共享状态，不能出现两套播放列表或假成功回执。

本轮范围：本地音频导入、故事库、播放/暂停/继续、切换音频、进度显示与调整、真实状态查询、App 内导航、语音回合与故事音频协调。2026-10-18 根据真机反馈补入：明确喊「小蓝同学」可优先打断正在进行的语音识别、模型处理或播报，真实自然完播状态回到对应小蓝会话；前台开启后，锁屏与后台继续完整智能体执行和语音交付，录音互斥保持。

不做生成故事、联网搜索/下载音源、内容推荐、儿童偏好或长期记忆、独立账号/云同步、外接故事机/音箱控制、儿童专用新前端，以及无需唤醒词的连续任意语音打断。明确唤醒词触发的打断与用户开启后的后台监听已纳入本轮。此次不引入音源内容；用户选择自己有权使用的本地音频。

## 3. 入口与主要流程

1. 在现有四列拓展网格的「工具」组增加「儿童故事机」原生入口；稳定路由为 `extension.stories`，父节点为 `extensions`，无需参数。
2. 打开已有 App 导航中的原生故事库页，二级页按现有规则隐藏 Tab，返回回到拓展。小蓝可通过现有 `app_navigation` 工具发现并打开该路由；目标页真实挂载后才返回 `visible`。
3. 空库显示一条简短说明和「导入音频」；文件选择器允许用户明确选择本地/文件 App 提供的音频。导入成功后进入同一个故事库，失败显示真实错误。
4. 点故事行选中并播放。原生列表上方的播放器显示当前标题、播放状态、已播时间与总时长，提供播放/暂停/继续、前后 15 秒、进度条和「换一篇」。工具栏支持多选文件导入；删除采用原生确认，删除当前故事前先停止播放。
5. 用户暂停后保留当前位置；继续使用当前故事和位置。换音频停止原音频并选中目标故事。播放完成有明确完成状态，不能继续显示正在播放。
6. 小蓝语音模式在既有拓展入口开启，故事页使用同一个跨页语音胶囊；不建立儿童故事专用语音页面或第二个会话系统。

导入、删除等文件管理操作由原生界面承接；首版语音工具只查询和控制已有故事。助手不能用任意路径、URL 或生成的名称创建一条音源。

## 5. 技术与音频架构

故事库、播放器、原生页面和 `story_player` 使用一份 App 内权威状态。库负责导入副本和元数据，播放器负责当前故事、真实播放状态、进度与音频所有权，界面和工具均调用这些入口，不直接修改持久化文件。

故事播放通过现有 `AudioSessionCoordinator` 的独立 `storyPlayback` intent 管理音频，不能绕过协调器调用 `AVAudioSession.setCategory/setActive`。普通媒体在开启小蓝时的既有处理不应被整体放开；只为受控故事播放器增加必要的共存/暂停协调。

| 场景 | 期望行为 |
|---|---|
| 故事播放，小蓝待命 | 故事播放时保留已开启的唤醒监听；本轮功能验收见第 17 节 |
| 唤醒或点击说话，开始收取指令 | 暂停故事，保存真实位置，避免故事声进入本次指令 |
| 小蓝处理中/播报 | 故事保持暂停；唤醒检测继续工作，用户再次明确唤醒可打断旧回合 |
| 识别、模型执行、提示音或 TTS 期间再次明确唤醒 | 优先接收新指令，取消旧识别、旧回合及播报，作废旧授权；新模型执行等待旧任务实际清理结束 |
| 本回合要求播放/继续/切换 | 记录显式播放意图；在语音采集/回复让出音频后执行，回执区分等待与实际播放 |
| 本回合要求暂停 | 保持暂停，回合结束后不被自动恢复覆盖 |
| 查询/其他回合 | 若仅因本次交互临时暂停，可在回合安全结束后按已有播放意图恢复；不复活已被用户暂停的音频 |
| 用户取消/关闭/暂停语音，或旧回调迟到 | 不误续播；语音回调不能覆盖新的手动播放意图，也不能恢复已暂停/切换的旧故事 |
| 开始录音、其他采集/媒体抢占或系统音频中断 | 录音优先，故事暂停；不自动恢复抢占前播放 |
| App 进入后台/锁屏 | 故事及用户已开启的小蓝采集、智能体和语音交付继续；撤销页面权限，系统中断仍真实暂停 |

未结束录音（包括暂停、中断待恢复、安全结束中）与小蓝独立语音的互斥门禁保留。故事的播放请求不能借道启动小蓝、结束录音、夺走录音音频或重新激活旧语音回调。

## 6. 数据与受控接口

### 6.1 本地故事库

每条音频模型为 `StoryAudio(id: UUID, title: String, fileName: String, duration: TimeInterval)`，保留用户可见标题、App 管理的相对文件名和时长。当前 App 的 `Application Support/Yima/story-player/` 中保存 UUID 命名音频副本和 `library.json`。外部文件通过文件选择器取得访问权后复制到该目录；不能把临时 security-scoped URL 当作永久音源。导入用 `AVAudioPlayer` 实际读文件检查有效音频和时长，保存后再发布条目；同名文件不覆盖既有副本。

故事库音频与清单持久化；当前选中故事与进度仅在本次 App 进程中保留，重启不恢复播放，不新增跨重启进度存储。损坏的清单或保存失败必须保留原始文件，不能用空库静默覆盖。工具和 UI 返回同一个库中的 ID；不向模型提供 App 容器绝对路径或音频字节。

### 6.2 `story_player`

通过现有 Agent 工具注册和权限管理暴露窄能力，仅提供给小蓝独立语音的交互主回合，包含该主回合的锁屏/后台执行；普通聊天、会中助手、后台子智能体和通知回合不提供。执行校验当前会话、执行 generation 与取消状态，页面展示另须前台解锁，避免过期回调改变用户正在听的音频。

| action | 输入与结果约束 |
|---|---|
| `list` | 返回真实 `stories: [{story_id, title, duration_seconds}]`；没有音频时返回空库 |
| `status` | 返回当前真实状态快照 |
| `play` | 额外且必须仅传 `story_id`，为库内真实 UUID；名称先通过列表解析，重名或无匹配先询问/选择 |
| `pause` / `resume` / `stop` | 操作当前故事；无当前故事时暂停/停止幂等返回 `stopped`，继续明确失败。停止清空当前选择，暂停保留进度 |
| `next` | 按故事库中的稳定顺序换一个故事；没有候选时如实说明 |
| `seek` | 额外且必须仅传 `position_seconds`，为 `0...当前 duration` 内的有限非负整秒，布尔值不算数字；非法参数不改变播放 |

除 `play/seek` 外，每个 action 只接受 `action` 字段。工具不接受任意路径、远端 URL、shell 命令或未经导入的标题；返回不暴露 `fileName`、URL 或音频字节。写入/播放状态改变通过同一主线程控制入口串行执行。共享工具参数 schema 使用整数秒；原生进度控件仍可使用 `TimeInterval`。

状态快照包含 `status`（`playing/paused/waiting_for_voice/stopped/finished`）、`playback_id`、`current_story_id`、`title`、`position_seconds`、`duration_seconds`、`error`（无错误时为 null）及 `play_requested`。`playback_id` 标识本次播放请求，与用于拒绝迟到回调的 delegate 世代分离；自动语音挂起/恢复保持该标识，重新播放或更换播放所属会话时产生新标识。控制动作返回 `action/message/state`，顶层 `status` 与实际快照一致；`list` 返回 `status=available`、`stories` 和 `state`。

自然完播另以 `story_playback` 被动通知持久写入对应小蓝会话，包含 `playback_id/story_id/title/status=finished/position_seconds/duration_seconds`。通知不是新用户指令，不自动续播、换篇、分派任务、跳页或播报；忙时保留待处理，空闲后进入历史。具体绑定、去重与恢复规则见第 13 节。

成功回执必须基于已完成操作。音频准备失败、会话不可用、未授权、无匹配、参数非法或被录音占用时返回明确失败。若播放被当前语音回合延后，必须返回等待/已安排及当前真实暂停状态，不能提前说“已经播放”。助手最终回答根据工具回执决定；页面跳转成功不能充当播放成功。

## 7. 状态、错误与恢复

| 状态 | 界面与工具行为 |
|---|---|
| 空库 | 原生空状态与导入动作；工具如实返回无故事 |
| 导入中 | 同一次选择按顺序导入；清单写入成功才发布条目，各文件失败分别汇总 |
| 选择取消 | 保持原库、选中项和播放状态 |
| 文件不可读/格式不支持/保存失败 | 展示具体可理解的错误；不发布半成品或覆盖已有数据 |
| 无当前音频 | 播放器说明先选故事；继续/进度操作返回无当前音频 |
| 正在播放/已暂停/已完成 | 标题与真实状态一致，时间来源于实际播放器 |
| 文件缺失或音频解码失败 | 保留条目和可恢复的错误提示，不假称播放；仍可选择其他故事 |
| 离线 | 本地故事和原生控件可用；依赖远端聊天模型的语音处理如实失败 |
| 录音冲突 | 保留录音，暂停/拒绝故事音频，说明先结束录音；不静默结束录音 |
| 音频中断/路由变化 | 保留位置并更新真实状态；恢复必须遵守当前播放意图与音频门禁 |

## 8. 隐私与数据生命周期

导入的音频副本和清单保存在当前 App 容器，开发/正式版彼此独立。此功能不自动上传音频，不扫描用户未选择的文件，不申请额外相机、照片或录音权限。语音沿用小蓝已有授权及模型配置，仅把用户指令和必要标题/状态交给模型。

删除条目需明确操作对象；仅清理 App 内该音频副本、对应元数据和失效选择，不删除文件提供方的原件。语音首版不提供导入/删除能力。App 数据清除或卸载后副本遵从系统容器生命周期；不引入跨容器备份或同步承诺。

### 15.3 锁屏文件准备与当前开发进度

锁屏验证必须覆盖新打开另一篇音频，不能仅确认锁屏前已经打开的文件继续播放。导入的文件、`library.json` 和目录原先没有显式设置文件保护级别，代码无法保证旧文件均可在锁屏后重新打开。目标仅为 App 管理的故事目录、清单与库内有效音频使用 `completeUntilFirstUserAuthentication`；不使用 `.none`，不修改其他 App 文件或外部导入源。该级别保留加密，设备重启后的首次解锁前仍不可用。[Apple 数据保护级别](https://support.apple.com/guide/security/data-protection-classes-secb010e978a/web)

已补入 `StoryLibraryStore.prepareForBackgroundPlayback() throws`，由前台启用小蓝流程调用：先验证本地目录、清单和全部库内音频，再对 iOS 文件设置上述保护；拒绝符号链接、缺失音频和损坏库，保护设置失败抛出可读错误。新导入副本在发布清单前设置保护，原子清单写入同时携带对应 `Data.WritingOptions`，使替换后的清单保留保护属性；macOS 宿主跳过 iOS 保护设置。

本轮不扩展 `StoryLibraryStore.init` 的临时保护错误自动恢复：若初始化时清单不可读，仍沿用既有不可用状态，不写入空库覆盖原文件。启动须在前台解锁并成功准备后进行；重启后首次解锁前的冷启动监听不在本轮范围。受保护数据暂不可读、旧导入文件保护准备及错误恢复均需单独核验。

`python3 tools/integration/verify_story_library.py` 已通过，覆盖前台准备保留清单和音频内容、空库不虚构清单，以及目录/音频/清单符号链接、缺失音频和损坏库拒绝；既有导入、删除与原子写失败回滚也通过。iOS 保护属性实际值及锁屏后新开音频尚未运行核验。
