## 1. 已确认需求与目标

用户明确选择：

1. 在 Yima 内显示手机原生地图，地点和标签保存在 Yima。
2. 首版由用户提供具体店名或地址，助手帮助保存、打标签，供以后导航。
3. 从“拓展”进入美食地图，首版由苹果地图承接导航。
4. 先制作可点击原型，评审地图、收藏列表和标签的展示及交互。
5. 原型评审后按该方案开发真实功能，小蓝能够通过语音查找地点并展示在地图上。

目标是把聊天中说过的餐厅或地点变成可再次找到的个人收藏。核心流程为：**说出地点与标签 → 解析并核对真实地点 → 本地保存 → 地图查看与标签筛选 → 导航到所选地点**。

“本地”在本需求中指 Yima 持有收藏和标签，不代表整套地图、地点查询、语音处理与导航均可离线运行。

## 2. 首版范围

| 能力 | 首版定义 |
|---|---|
| 口述收藏 | 通过现有聊天或小蓝入口表达具体店名、地址和标签；也能使用文字输入 |
| 地点核对 | 将店名或地址解析为真实地点；重名、分店或位置不明确时先让用户补充或选择 |
| 本地收藏 | 保存名称、地址、可用于地图的坐标和用户标签，重开 App 后保持 |
| 地图与列表 | 在 App 原生地图查看收藏；提供同一批地点的列表，支持文字查找和标签筛选 |
| 收藏维护 | 可以修改标签、删除收藏；再次收藏同一地点时避免静默产生重复记录 |
| 发起导航 | 从明确选中的收藏地点进入地图导航流程 |

首版不包含“根据口味、预算等条件主动推荐餐厅”。跨设备同步、共享地图、评价打分、打卡相册、离线地图包、行程规划和自动写入其他地图 App 收藏夹，不纳入本轮交付。

## 3. 典型场景与流程草案

示例店名为虚构内容：用户说“把杭州河畔面馆文一路店保存到美食地图，标签是面食、想去”。

1. 助手提取地点描述和用户明确提供的标签。
2. 使用现有地点搜索或地址解析能力查找；缺少必要城市、区域时追问，不默认为用户当前位置。
3. 若存在多个分店，先展示或口头说明带地址的候选，由用户选择。选定真实地点后发起收藏核对弹窗，展示名称、完整地址和最终标签；即使口头已说“收藏”，也必须点击“确认收藏”后才写入。用户于 2026-10-20 真机试用后明确选择此流程，替代首版的明确指令直接保存规则。
4. 仅在本地写入成功后回复“已保存”，附名称、地址和标签；未查到、未选定或写入失败时不声称完成。
5. 用户以后可以说“打开我的美食地图”“看看标了想去的店”，也可以触摸进入页面。
6. 用户点选或说出明确收藏后发起导航；重名收藏先选择目标。

标签为用户可编辑的文字，不预设必须使用的分类。助手可从明确指令中提取标签；未提供标签时允许无标签保存，不擅自添加“好吃”“推荐”等评价。

## 4. 页面与信息架构提案

用户已确认从现有“拓展”增加一个“美食地图”原生入口，并由苹果地图承接导航。已注册到现有 App 导航路由，供聊天和小蓝打开。保持四个一级 Tab。

- 主页面：原生地图、收藏查找与标签筛选、当前结果列表。地图和列表使用同一份筛选结果。
- 选中地点：用原生详情 Sheet 展示名称、完整地址、标签，以及导航和编辑操作。
- 地点核对：候选显示完整地址，不能只显示同名店名。对话/小蓝发起收藏时，在当前页面弹出原生核对窗口，展示名称、完整地址、地址下方的原生位置地图和最终合并标签，提供“确认收藏”和“取消”；不通过跳转地图代替确认。手动添加沿用展示名称、地址、标签的原生保存表单。
- 返回：遵守现有导航；进入二级页面隐藏主 Tab，返回恢复。语音胶囊延续现有行为。

2026-10-20 产品负责人明确表示“这个原型可以，就按这个方案开始开发”，地图/收藏切换、标签筛选、地点详情及添加流程据此进入原生实现；真机视觉和交互仍需验收。

## 5. UI/UX 风格依据

风格状态：已确认复用既有设计系统，且产品负责人已通过可点击原型并授权原生开发。沿用原生、安静、单色控件；苹果地图交接使用系统外链语义的蓝色。

复用已批准的项目级 `DESIGN.md`，包括 Aesthetic Direction、Typography、Color discipline、Spacing、Layout、Buttons、Accessibility 和 Prohibited Patterns；适用基线为 2026-08-03 及截至 2026-10-17 的增补。

- 关键词：原生、安静、清楚、内容优先；避免装饰渐变、彩色卡片堆叠、桌面式多栏和营销插画。

平台可行性参考：[MapKit for SwiftUI](https://developer.apple.com/documentation/mapkit/mapkit-for-swiftui) 的地图与标记能力、[MKLocalSearch](https://developer.apple.com/documentation/mapkit/mklocalsearch) 的地点查询，以及 [MKMapItem.openInMaps](https://developer.apple.com/documentation/mapkit/mkmapitem/openinmaps(launchoptions:)) 的地图交接。用户已确认首版交给苹果地图承接导航；其他地图 App 不纳入首版。

## 7. 数据与接口契约

最小地点记录包含稳定 UUID、名称、地址、MapKit 原始坐标、`coordinateSource=mapkit`、标签、递增 revision、创建与修改时间。数据以 `schemaVersion=1` 的 JSON 原子写入当前应用的 `Application Support/Yima/places.json`；开发与正式应用容器隔离。

- 解析结果与收藏分开：临时候选不会自动成为已保存收藏。
- 重复处理：标准化名称与完整地址均相同，且原始 MapKit 坐标距离不超过 30 米时才合并；相似名称不能单独作为依据。
- 用户再次明确要求收藏同一地点并增加标签时，更新已有记录，保留原有标签。
- 编辑与删除使用稳定 ID 和 revision；界面与 Agent 更新同一个可观察数据源。临时搜索候选会解析到真实收藏 ID，避免跨入口保存后出现重复标记或过期标签。
- 保存失败保留当前输入与候选；损坏数据不可按空收藏覆盖。

坐标契约：只接受本功能实际 MapKit 查询返回的坐标，保留原值用于 MapKit 标记与 `MKMapItem` 导航交接。不接收模型提供的坐标，不导入既有 CLI 的 WGS-84/GCJ-02 字段，不猜测坐标系或手工二次转换。实际地区的标记、完整地址与苹果地图目的地一致性仍须真机核验。

`yima_places` 提供 `search/list/get/save/update_tags/delete/show/navigate`。搜索返回当前会话的真实 `search_id` 与 `candidate_id`；新搜索使旧候选失效，候选最多保留 30 分钟。收藏只能从该候选发起；`save` 等待前台解锁状态下的真实弹窗按钮确认，模型参数和口头指令不能绕过。取消、后台、锁定、请求失效、候选被新查询替代和等待超时都不写入；没有可用展示位置时提示先关闭其他弹窗。标签在核对期间变化则刷新最终标签并要求再次确认；写入失败保留弹窗与错误以便重试。已出现的确认窗口持续拥有展示权直到实际关闭，之后才恢复当前请求原先仍有效的导航绑定。

展示用原生临时结果快照，不自动写入收藏。搜索来源始终标为“搜索结果”，按当前筛选实时显示已收藏/未收藏数量和行状态，不能把搜索来源误当成尚未收藏。搜索和展示工具回执同样区分 `source` 与实际 `saved`、`saved_count`、`unsaved_count`。`show/navigate` 要求当前页面版本与前台解锁状态；小蓝同时核验当前执行代次和导航绑定，子 Agent、会议助手和完成通知回合不能调用。

`show` 只有页面实际挂载并应用请求后返回 `visible`；苹果地图只在系统接受交接后返回 `handoff_accepted`，不把交接说成已经开始导航。标签更新/删除使用收藏版本，旧版本操作失败并要求重新读取。

收藏或标签保存完成后默认停留当前页面，只报告真实结果。只有用户在本轮明确要求打开地图、展示地点或导航时，才调用展示/导航工具；“收藏并在地图上展示”可以在确认弹窗实际关闭后，重新读取页面版本并用保存回执的真实地点 ID 展示。核对窗口中的内嵌地图仅用于核对位置，不构成页面跳转授权。

## 8. 状态、权限与恢复

| 状态 | 预期行为 |
|---|---|
| 尚无收藏 | 清楚说明可以说店名或地址添加，仍可通过现有聊天入口开始 |
| 正在查找 | 显示查找状态，不提前显示已保存 |
| 无结果/多个分店 | 保留原话，允许补充地址或选择候选 |
| 网络不可用 | 已存地点与标签可从本地列表读取；在线搜索、底图和导航按实际可用性说明，不假称可用 |
| 定位未授权 | 手工提供城市/地址仍可收藏和查看；拒绝定位不阻止本地收藏管理 |
| 保存失败 | 不生成成功回执，保留输入并允许重试 |
| 收藏待确认 | 当前页面弹窗核对名称、完整地址和最终标签；点击确认才写入，取消/失效不保存；不自动反复弹窗 |
| 导航交接失败 | 收藏仍在，说明未能打开导航，不重复创建收藏 |
| 删除收藏 | 明确确认删除；只移除该收藏，不删除聊天或其他业务内容 |

地点与标签保存在当前 Yima 容器，开发版和正式版沿用既有隔离。不为本功能新增后台定位或持续轨迹采集；仅请求当前位置时使用必要定位权限。启用该用途前，核对正式版与开发版定位说明：当前使用期间定位文案主要解释录音用途，需要覆盖新增的地图用途。

“保存在本地”不等于没有外部请求：地点解析会使用地图服务；通过现有远端聊天模型处理的地点和标签遵守当前会话模型与工具授权，不另行上传整份收藏库。

用户反馈“待选地点”点入后已收藏，没有保存确认键。代码检查确认：首版 Agent `save` 按明确收藏指令直接写入，而搜索快照的来源标记没有跟随真实收藏状态变化；不存在藏在对话中的确认弹窗。上一轮操作说明把手动添加路径套到了语音路径，已纠正。

产品负责人随后明确选择“先弹窗核对名称、地址和标签，确认后再保存”。本轮据此新增共享原生确认管理器与窗口，接入当前页面，不新建聊天前端或地图确认页。小蓝等待确认期间只停止监听，保留待执行工具的代次；普通暂停会取消执行，不能复用。地图/列表及工具回执改为显示真实收藏状态。编译、安装与手动验收边界见[检查记录](../testing/food-map.md)。

用户随后要求在完整地址下面增加地图，核对大概位置。内嵌地图显示该候选的原始 MapKit 坐标，初始视野约 1.2 km，可平移和缩放查看周边，不获取当前位置、不修改收藏坐标；保留可滚动内容与固定底部确认/取消。用户同时明确保存后不自动跳页，主聊天、小蓝提示词与工具说明据此要求只有明确展示/导航指令才换页。
