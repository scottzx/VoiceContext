## 访问方式

在仓库根目录启动本地静态服务器：

```bash
python3 -m http.server 4173 --directory docs/design/v1/prototype
```

浏览器打开：

```text
http://127.0.0.1:4173/
```

不要直接用 `file://` 打开。Codex 内置浏览器会将每个 `file:` URL 当作独立安全源，可能拒绝同页 frame 或链接；本地 HTTP 地址可避免该限制。

## 覆盖页面和主路径

- 首次引导：本地隐私、麦克风权限（允许与拒绝）、不依赖 iCloud 的使用说明。
- `记录`：个人语音、多人讨论和会议共用平面日历 Recording 列表；底部为独立红色录音圆钮，右上角进入「我的」，录音中在全局显示可停止状态条。
- `开始记录`：把「直接开始录音」放在可选字段之前；可选「作为会议整理」并填写主题、参与人和纯文本议程。
- `录音中 → 停止确认 → 处理中 → Recording 详情`：两种入口使用同一录音、处理和详情结构。
- `Recording 详情`：先显示音频播放器与 15 秒快退/快进、倍速，再显示逐字稿、片段、说话人、可选会议字段、7 天保留、导出和 Skill 条件。
- `我的`：试用 / 购买 / 恢复、iCloud、本地导出、保留、Skill、隐私与离线许可。
- `状态画廊`：权限、系统中断、后台积压、低存储、iCloud 错误、转写失败、试用耗尽和身份状态。

## 走查脚本

1. 在「记录」底部点「开始记录」，不填写字段，直接开始录音、停止、开始处理、模拟处理完成；确认到达个人语音详情，音频播放器位于文稿之前。
2. 返回「记录」，重新开始，开启「作为会议整理」并填写可选字段，重复停止与处理；确认仍进入同一个详情结构，且会议只增加结构字段。
3. 开始录音后从右上角进入「我的」；确认全局录音条持续显示时长、处理说明和直接「停止」。
4. 打开首页的「一个关于 onboarding 的想法」；确认短个人独白被当作完整 Recording，而不是要求补会议字段。再切换「长期保留」。
5. 打开「研究笔记」；确认音频已清理但文稿、日历记录和导出仍存在。
6. 在「我的」分别打开 iCloud、存储、购买和 Codex Skill；确认本地 fallback、音频边界、试用锁定和会议 Skill 条件清晰。
7. 打开「状态画廊」，逐项检查每个状态都写出事实、保留的数据和可进行的操作，不只用颜色表达。

## 高保真验收边界

- 原型以 iPhone 15 的 393 pt 宽度设计，并定义浅色 / 深色 token、最小 44 pt 触控目标、Dynamic Type、VoiceOver 与 Reduce Motion 标注。
- 当前 Xcode 工程仍是模板页面；本原型和 `design-system.md` 是后续 SwiftUI 实现任务的视觉及交互依据。
- 真机设计走查与无障碍验收属于 PM `#41`，不能被网页原型替代。
- Apple Voice Memos 仅提供视觉克制、平面列表和录音红的方向，不复制 macOS 窗口或双栏布局。钉钉 A1 仅提供低门槛录音、底部控制和播放器优先层级；实时翻译、云端总结、硬件连接与复杂模板不进入 VoiceContext v1。
