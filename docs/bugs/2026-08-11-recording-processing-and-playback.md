## 1. 问题摘要

真机新录音暴露出三个需要继续处理的问题：停止录音后，分钟级任务之外又创建了一个整段转写任务；最后一个录音分片已经完成，却残留“需要跨片续接”标记；音频源文件本身有效，但用户反馈详情页无法播放。

此前发现的长录音详情页闪退已经在当前代码中完成修复：播放器改为单实例懒加载，VAD 和 Metal 输入增加长度上限；同一台真机上的历史任务已完成，完整测试 66/66 通过。本项将它保留为回归验收，不重新引入第二套播放器或整段推理路径。

## 2. 真机证据

### 2.1 新录音 A：约 81 秒

- Recording：`90035C44-B806-44AA-ABC4-FAEE2BBF2E9D`
- 物理音频分片：60 秒 + 20.18 秒。
- 分片转写任务：均一次完成。
- 额外存在一个 `chunk_id = NULL` 的整段转写任务，并已完成。

### 2.2 新录音 B：约 48 秒

- Recording：`52A09F95-0DF5-4F95-9EB5-421B600FB752`
- 物理音频分片：47.89 秒。
- 分片转写任务：一次完成。
- 额外存在一个 `chunk_id = NULL` 的整段转写任务，并已完成。
- 录音已完成，但该分片 `requires_continuation = 1`，标记没有在最终转写后清除。

### 2.3 音频文件完整性

三个音频文件均可被 `ffprobe` 正常读取，编码为 AAC、16 kHz、单声道，时长与索引基本一致。因此“无法播放”目前更像是详情页播放器状态、分片切换或播放会话管理问题，不应通过重新录音或删除音频处理。

## 3. 待修复 Bug

### BUG-01：停止录音后重复创建整段转写任务

**现象**：每个新 Recording 已经在分片关闭时创建了带 `chunk_id` 的任务；停止录音时，`RecordingCoreModel.stop()` 又调用一次不带 `chunkID` 的 `enqueue`，生成旧版整段任务。

**影响**：

- 同一条录音可能被转写两次。
- 增加模型加载、耗电和发热。
- 整段任务的结果可能与增量文稿竞争写入。
- 任务列表出现一个无法对应具体分片的旧任务。

**修复要求**：

- 分钟级队列启用后，停止录音不得再创建 `chunk_id = NULL` 的整段转写任务。
- 保留旧数据中的整段任务兼容读取，但不得为新 Recording 产生该类型任务。
- 对已有“分片任务 + 整段任务”的 Recording，启动恢复时将整段任务标记为 superseded，不重复执行。
- 文稿只能由分片任务按 source chunk 幂等合并。

**验收标准**：

- 新录制一条超过 60 秒的音频后，任务表只存在对应分片任务。
- 停止录音、杀进程、重新启动各一次，任务数量不增加。
- 同一分片最多执行一次成功提交；失败重试不会产生第二个任务。
- 既有真机数据可以迁移，且不会删除音频或文稿。

### BUG-02：最终分片残留跨片续接标记

**现象**：录音 B 已完成，文稿也已完成，但最后一个分片仍为 `requires_continuation = 1`。

**修复要求**：

- 只有当前分片确实需要等待下一分片时才保留标记。
- 录音停止后，如果没有下一分片，最后一个分片必须在最终处理完成时清除标记。
- 跨片转写成功后，同时清除上一分片和当前分片的待续接状态。
- 重试、重复启动和文稿已存在的恢复路径必须幂等。

**验收标准**：

- 结束录音后，最后一个有效分片的 `requires_continuation = 0`。
- 一个分片跨边界转写成功后，相关分片均为 0，文稿不重复、不丢字。
- 中途杀进程后恢复，标记不会永久卡住任务。

### BUG-03：详情页音频无法播放

**现象**：用户反馈详情页进入后无法播放音频。

**已知事实**：源文件为有效 AAC 16 kHz 单声道，索引路径和实际文件存在性检查通过。

**排查范围**：

- 详情页加载完成后，播放按钮是否仍被错误判定为不可用。
- 统一时间轴是否正确加载第一个分片并在分片结束时切换下一个。
- 暂停、拖动、切换速率、返回详情页后再次进入是否破坏播放器状态。
- 录音分片只有一个和分片超过一个时，是否表现一致。
- 播放器加载失败时是否显示明确状态，而不是静默无响应。

**修复要求**：

- 继续使用单实例懒加载播放器，任意时刻最多持有当前分片一个 `AVAudioPlayer`。
- 播放、暂停、±15 秒、拖动和速率切换都作用于统一时间轴。
- 播放跨分片时，累计时间不得跳回 0。
- 音频有效但某个分片不可读时，显示可读错误并允许跳过该分片；不能导致 App 闪退。

**验收标准**：

- 48 秒单分片录音可以从 0 秒播放到结束。
- 81 秒双分片录音可以连续播放并正确显示总时长。
- 进入详情页 30 秒、播放、暂停、拖动、返回再进入均不闪退。
- 两小时录音详情页不一次性创建 114 个播放器。

## 4. 回归要求

- 完整单元测试保持通过。
- 真机覆盖：短录音、跨 60 秒录音、历史两小时录音。
- 验证冷启动、后台返回、杀进程恢复、详情页播放和重复进入详情页。
- 不得通过清除 App 数据规避问题；测试必须保留已有音频、数据库和文稿。

## 5. 不在本 Bug 文档中解决的事项

- 说话人识别开关和默认模式：见导入/转写功能方向以及后续说话人需求。
- 导入其他音频并转写：见 [`docs/features/import-audio-transcription.md`](../features/import-audio-transcription.md)。
- 转写准确率、断句和语病：作为转写质量增强项，不能通过把任务重新跑一遍来掩盖。
